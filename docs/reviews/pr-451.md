# PR #451 로컬 리뷰 — feat: RAG 1차 Embedder·VectorStore 어댑터와 로컬 Ollama 임베딩 전환 (#440·#450)

## Review Summary

RAG 1차의 임베딩·벡터 저장소 어댑터를 추가하고, 실제 임베딩을 로컬 Ollama `bge-m3`로 만들도록
전환하는 PR입니다. 커밋은 핸드오프 두 건, Codex 구현 두 건(#440, #450), orchestrator의 ADR·설계
갱신 한 건으로 구성됩니다.

**Part A — 어댑터 계층(#440, 설계 438 §4.1·§4.2, ADR-018 R4).** `app/adapters/embedding/`에
`Embedder` ABC, `OpenAIEmbedder`, `MockEmbedder`가 생겼습니다. `OpenAIEmbedder`는 OpenAI 호환
`/v1/embeddings`를 100건 단위로 호출하고, 응답 `index`로 순서를 복원하며, 차원 불일치는
`EmbeddingDimensionError`로, SDK 오류는 `EmbeddingError`로 바꿉니다. `base_url`이 없으면 공식
엔드포인트를 명시해, SDK가 환경변수 `OPENAI_BASE_URL`(LLM 프록시)을 따라가지 않게 했습니다.
`app/adapters/vector/`에는 `VectorStore` ABC와 `PgVectorStore`, `InMemoryVectorStore`, 값 객체
`ChunkRecord`·`ChunkFilter`·`ChunkHit`이 생겼습니다. `ChunkFilter`는 값만 담아 저장소 중립 규칙을
지킵니다. `PgVectorStore`는 `ON CONFLICT DO UPDATE`와 `cosine_distance`를, 인메모리 구현은 같은
필터·정렬 규칙을 Python으로 구현합니다. 설정 다섯 개와 `get_embedder()`, `get_vector_store(db)`가
factory에 추가됐고, 테스트에서는 두 provider가 `mock`으로 고정됩니다. PR #449 리뷰 S1(중복 skip)도
정리됐습니다.

**Part B — 로컬 Ollama 전환(#450, ADR-018 §2a).** `EMBEDDING_DIMENSIONS`를 1024로 바꾸고, 새
마이그레이션 `c3d4e5f60070`이 HNSW 인덱스를 지운 뒤 행을 비우고 컬럼을 `vector(1024)`로 바꿔
인덱스를 다시 만듭니다. 머지된 `c3d4e5f6006f`는 손대지 않았습니다. compose에 `ollama` 서비스가
추가되고, `backend`·`worker`가 `http://ollama:11434/v1`을 씁니다. 기본값은 `bge-m3`와
`http://localhost:11434/v1`이며, 키 없이 base URL만 있으면 더미 키를 씁니다.

이번 리뷰는 저장소 중립성(R4), 두 구현체의 동작 일치, 마이그레이션 안전성, 실제 Ollama·pgvector
종단 동작을 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 마이그레이션 테스트가 "현재 head"를 고정해 다음 마이그레이션에서 깨집니다 — 중간, 다음
마이그레이션을 추가할 때 함께 수정 필요.** `tests/rag/test_embedding_migration.py`의
`test_embedding_migration_head_and_model_dimension`은 `script.get_heads() == ["c3d4e5f60070"]`를
단언합니다. 어떤 도메인이든 새 마이그레이션이 추가되면 이 테스트가 무관하게 실패합니다. 검증하려는
것은 "이 revision이 `c3d4e5f6006f` 다음이고 모델 차원과 맞는다"이므로, head 비교를 빼고
`get_revision(REVISION).down_revision`과 차원 일치만 남기면 됩니다. 같은 테스트의 `== 1024`
리터럴도 상수와 중복입니다. 지금 머지를 막지는 않지만, 다음 마이그레이션 PR이 이 테스트를 고치게
되므로 #441 핸드오프에 정리 항목으로 넣겠습니다.

**S2. compose `environment`가 `.env`의 `EMBEDDING_BASE_URL`을 덮어씁니다 — 경미, 허용.**
compose에서는 `environment`가 `env_file`보다 우선합니다. 그래서 compose 안에서는 `.env`로 임베딩
엔드포인트를 바꿀 수 없습니다. 현재는 compose 안에서 Ollama 서비스를 쓰는 것이 의도이므로 문제가
아닙니다. 다른 엔드포인트가 필요해지면 `${EMBEDDING_BASE_URL:-http://ollama:11434/v1}` 형태로
바꾸면 됩니다.

**S3. `PgVectorStore.upsert`가 행마다 INSERT를 실행합니다 — 경미, 허용.** 배치 크기가 100건(가정)이고
임베딩 계산(청크당 1~3초)이 병목이라, 행 단위 실행 비용은 무시할 수준입니다. backfill 시간이 실제로
문제가 되면 다중 VALUES로 바꾸면 됩니다.

## Questions

**Q1. 실제 Ollama와 pgvector에서 종단 동작하는가 — 리뷰 중 확인해 해소했습니다.** 임시
`pgvector/pgvector:pg16` 컨테이너에 전체 마이그레이션을 올리고, `get_embedder()`(실제 Ollama
`bge-m3`)와 `get_vector_store()`로 뉴스 4건을 적재해 `asset_id=10` 필터로 검색했습니다. 필터
밖의 금리 기사는 제외됐고, 질문 "엔비디아 실적은 어땠나?"에 실적 기사가 0.654로 1위,
출하 지연 기사가 0.519, HBM 기사가 0.457 순이었습니다.

**Q2. Ollama 모델이 아직 없을 때의 동작 — #441에서 다룹니다.** compose를 처음 띄운 직후에는
`bge-m3`가 받아져 있지 않아 임베딩 호출이 실패합니다. 설계 438 §3에 따라 임베딩 job은 실패한
배치를 건너뛰고 다음 실행에서 다시 시도하므로, #441 구현에서 이 경로를 테스트로 확인하겠습니다.
모델 준비 절차는 설계 438 §13에 있습니다.

## Documentation Impact

- ADR-018에 §2a(임베딩 provider 결정, 근거, 속도 대가)를 추가했습니다. `docs/decisions/`는
  protected 디렉터리이며, orchestrator가 결정 반영 목적으로 수정했습니다.
- 설계 438의 §2.2(차원), §4.1(설정·factory), §9 OQ1(해소)을 갱신하고 §13(Ollama 준비 절차)을
  추가했습니다. `.env.example`도 새 기본값으로 바뀌었습니다.
- 새 ADR은 필요 없습니다. ADR-018 범위 안의 provider 결정입니다.
- Failure Record는 필요 없습니다.

## Final Recommendation

머지 가능합니다. 어댑터 시그니처에 SQL 표현이 드러나지 않는지(R4), 두 구현체가 같은 시나리오에서
같은 순서를 내는 공용 테스트가 있는지, 마이그레이션이 머지된 revision을 건드리지 않고 단일 head를
유지하는지, 임베딩 base URL이 LLM 프록시를 상속하지 않는지를 확인했습니다. 범위는 #440·#450에
한정되고 임베딩 job과 API는 들어오지 않았습니다. protected 파일 변경은 ADR-018 §2a 추가뿐입니다.
테스트는 Mock 결정성, OpenAI 호환 호출의 배치·순서·오류 변환, 인메모리 저장소의 필터·정렬·멱등성,
factory 분기, pgvector 통합(upsert, 필터 검색, 삭제, 점수), 마이그레이션 SQL 순서를 덮습니다.
Blocking은 없습니다. S1은 다음 마이그레이션 전에 고쳐야 하므로 #441 핸드오프에 넣고, S2·S3는
허용합니다. Q1은 해소했고, Q2는 #441에서 다룹니다.

최종 머지 권한은 개발자에게 있습니다.
