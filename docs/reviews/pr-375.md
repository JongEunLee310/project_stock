# PR #375 로컬 리뷰 — 뉴스 인텔리전스 개요·이벤트 피드·브리핑 근거 검증 (#301·#302)

## Review Summary

뉴스·공시 인텔리전스(에픽 #307) 1차 계약의 두 번째 단위로, 개요 BFF와 이벤트 중심 피드를 추가합니다. #305 모델 브랜치 위에 스택된 PR이며 커밋은 1건입니다.

**Part A — 개요·이벤트 피드(#301, 설계 §4.1·§4.2).** `GET /api/v1/news-insights/overview`는 요약 지표 4종(high_importance_events·sentiment_shifts·active_topic_clusters·fund_flow_signals, 각 `{count, change}`)과 브리핑을 반환하고, `GET /events`는 이벤트 중심 피드를 opaque cursor pagination으로 반환합니다. 라우터는 `app/api/v1/endpoints/news_insights.py`에 신설하고 `router.py`에 prefix `/news-insights`로 등록했습니다. 피드 item은 `importance{level,score}`와 `sentiment{direction,score}`를 분리 필드로 두고 `evidence_count`·`topic_ids`를 포함합니다. cursor는 `app/core/pagination.py`에 추가한 `encode/decode_datetime_cursor`(`detected_at`+`id` 기반)를 사용하며, 응답 메타는 `app/core/response.py`에 추가한 `cursor_paginated`/`CursorPageMeta`로 내려갑니다.

**Part B — 브리핑 근거 검증(#302, 설계 §4.3).** 브리핑은 별도 엔드포인트가 아니라 `/overview` 응답에 포함됩니다. `briefing.py`의 `validate_evidence_event_ids`가 각 highlight의 `evidence_event_ids`를 존재하는 이벤트 ID의 부분집합으로 걸러내고(존재하지 않는 ID 제외 + 중복 제거), 유효 근거가 없는 highlight는 제외합니다. 숫자(count·score)는 service·repository 집계에서 나오고 브리핑 문구는 seed 기반 고정입니다(1차).

재사용한 것은 `get_current_user`·`get_db`·`ApiResponse`/`success` 엔벨로프이고, 새로 추가된 것은 news_insights 도메인의 schema·repository·service·briefing과 core pagination/response의 cursor 지원입니다. 이번 리뷰는 계약 일치, 공용 core 파일 확장의 하위호환성, 범위 이탈 여부를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 공용 core 파일(`pagination.py`·`response.py`) 확장 — 설계가 authorize한 additive 변경, 하위호환 확인됨.** cursor pagination을 위해 `pagination.py`에 `DateTimeCursor`·`encode/decode_datetime_cursor`를, `response.py`에 `CursorPageMeta`·`cursor_paginated`·`PaginatedApiResponse`를 추가했습니다. 설계문서 와이어 컨벤션이 "cursor pagination 필수, `app/core/pagination.py` 확장"을 명시하므로 범위 내입니다. 기존 함수는 동작이 바뀌지 않았고(`paginated()`는 여전히 `PageMeta` 반환, 반환형만 하위 클래스 `PaginatedApiResponse`로 좁혀짐), `ApiResponse.meta`는 `PageMeta | CursorPageMeta | None`로 widening만 됐습니다. 기존 `paginated()` 호출부에 대한 회귀는 `mypy .`(457파일)과 `pytest`(1000건, 기존 페이지네이션 엔드포인트 포함) 통과로 확인했습니다. 후속 조치는 불필요합니다.

**S2. `market`·`portfolio_id`가 수용되지만 조회 범위에 적용되지 않음 — 1차 seed 계약의 알려진 한계.** 두 파라미터는 검증·수용되나 #305 모델에 시장·포트폴리오 연결 컬럼이 없어 실제 필터로 작동하지 않습니다. 1차는 seed mock 위 계약 고정이 목적이므로 허용 가능하며, 실데이터 연동 시 저장 모델 연결이 필요합니다. PR 본문에 명시돼 있어 추적 가능합니다.
