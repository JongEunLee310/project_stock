# PR #201 로컬 리뷰 — feat: LLM cloud 경로 마감 (BE #200)

## Review Summary

Epic #141 Phase 1의 후속 마감(BE #200)으로, 구조적으로는 완성돼 있던 cloud 경로의 미완
지점 세 가지를 채우는 PR입니다. `LLMGateway.complete_json`이 실행 메타를 담은
`LLMCompletionResult(output, provider, model_name)`를 반환하도록 바뀌었고(설계 076
Decision UU), 메타 값은 라우팅 키가 아니라 client 구현체가 노출하는
`provider_name`·`model_name`에서 채웁니다(Decision VV — mock 조립 시 라우팅 키와 무관하게
`mock`으로 남는 것이 의도된 동작입니다). `LLM_TIMEOUT_SECONDS`는 factory에서 게이트웨이
생성자로 주입되어(Decision WW) 모든 분기의 `client.complete_json(timeout=...)`으로
전달되고, OpenAI 모델명은 신규 `OPENAI_MODEL` 설정으로 분리됐습니다(Decision XX).
`LLMAnalysisService`는 성공 run에 `model_name`·`provider`를 기록해 지침
(`docs/knowledge/llm-data-pipeline.md`) §3.5의 추적성 요구를 마감합니다.

반환 타입 변경의 파급은 게이트웨이 호출부 4곳(llm_analysis·portfolios·watchlists·
dashboard)에 한정되며 모두 `.output` 접근으로 최소 적응됐습니다. Protected Files
(`llm_analysis/model.py`·`repository.py`, `privacy.py`·`router.py`·`prompts/`,
`worker/jobs/llm_analysis.py`, alembic)는 변경되지 않았고, DB 스키마 변경도 없습니다.
구현은 Codex가 핸드오프 `.codex/tasks/task-139-llm-cloud-path.md` 기준으로 수행했습니다.

## Suggestions

- **S1. 실패한 run에는 provider·model_name이 기록되지 않습니다.** `mark_failed`는
  `error_message`만 저장하므로, timeout이나 provider 오류로 실패한 run은 어느 provider·
  모델에서 실패했는지 run 자체에 남지 않습니다. 성공 run의 재현성(§3.5)은 이번 변경으로
  충족되므로 머지를 막지 않지만, provider 장애를 실데이터로 분석하게 되는 시점(Phase 2
  fallback #137)에 실패 경로 메타 기록을 함께 다루면 좋겠습니다.
- **S2. `theses/conflict_service.py`·`news/service.py`의 직접 호출 경로는 여전히 timeout이
  전달되지 않습니다.** 두 곳은 게이트웨이를 거치지 않고 `LLMClient`를 직접 사용하는 이전
  세대 경로라 설계 076이 명시적으로 범위 밖에 뒀습니다. 게이트웨이 경유로 수렴하는 리팩터가
  후속 과제로 남습니다.
