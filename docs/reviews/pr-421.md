# PR #421 로컬 리뷰 — 인증·설정 계약 강화 — SECRET_KEY 프로덕션 fail-fast·decode_token 계약 명시 (#418)

## Review Summary

전면 코드 분석(2026-07-24)에서 확인된 인증·설정 계약의 취약 지점 두 가지를 방어 코드와 계약 명시로 강화하는 단일 관심사 PR입니다. 커밋은 한 건이며 구현·테스트·핸드오프 문서(`.codex/tasks/task-418-auth-config-contract.md`)가 함께 들어 있습니다.

`app/core/config.py`에는 기존 `validate_cors_credentials`와 동일한 `@model_validator(mode="after")` 패턴을 재사용해 `validate_production_secret_key`를 추가했습니다. `APP_ENV=="prod"`이면서 `SECRET_KEY`가 기본값 `"change-me-in-production"`이면 `Settings` 초기화 단계에서 `ValueError`로 부팅을 차단합니다. `app/core/security.py`의 `decode_token()`에는 이 함수가 서명·만료만 검증하며 토큰 `type` 확인은 호출자 책임임을 밝히는 한국어 docstring을 추가했고, 검증 로직 자체는 바꾸지 않았습니다. 계약 변경은 없으며, 런타임 동작이 달라지는 지점은 `APP_ENV="prod"` + 기본 SECRET_KEY 조합뿐입니다.

이번 리뷰는 스코프 준수(로직 무변경)와 실제 코드베이스 계약과의 정합성을 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. `decode_token` type 검증의 계약화는 docstring에 머무름 — 현재 범위에서 허용, 후속 선택 사항.** 호출자 책임을 런타임으로 강제하지 않고 docstring 계약으로만 명시했습니다. 이는 핸드오프의 Out of Scope("type 검증을 `decode_token` 내부로 이동 금지")를 정확히 지킨 결과이며, 현재 호출자 두 곳(`app/api/v1/deps.py`, `app/domains/users/service.py`)이 모두 `type`을 검증하고 있어 실질 위험은 없습니다. 향후 `decode_token`에 `expected_type` 인자를 두는 방식은 별도 판단 사항으로 남깁니다.

## Questions

**Q1. 핸드오프의 "production"이 실제 허용값 `"prod"`를 의미하는지 — 리뷰 중 확인해 해소.** 핸드오프 본문은 "production"으로 적었으나 `APP_ENV`는 `Literal["dev", "test", "prod"]`로 정의되어 있습니다(`config.py:10`). Codex는 `"prod"`로 구현했고, 이는 `app/core/logging.py:58`의 기존 `APP_ENV == "prod"` 판별과 일관됩니다. 코드베이스의 실제 리터럴에 맞는 정확한 해석으로 확인해 해소했습니다.

## Documentation Impact

문서 갱신은 이 PR 범위에서 불필요합니다. docstring 언어·컨벤션 명문화는 별도 이슈 #420에서 다룹니다. ADR은 불필요합니다 — 새 도메인·테이블·외부 의존성·아키텍처 결정이 없고 기존 설정 검증 패턴(`validate_cors_credentials`)의 확장이기 때문입니다. Failure Record도 불필요합니다 — 장애 대응이 아니라 예방적 방어 코드 추가입니다.

## Final Recommendation

머지 가능합니다. 핸드오프의 Goal 네 항목(prod+기본키 실패, 그 외 환경 정상, `decode_token` 계약 docstring, 단위 테스트)이 모두 구현·검증됐고, Out of Scope로 지정한 `decode_token` 로직·시그니처는 diff상 변경되지 않았습니다. Protected Files는 없으며 그 외 파일 변경도 없습니다. 추가된 테스트는 prod/default(실패)·prod/custom(정상)·dev·test/default(정상) 세 경로를 덮어 새 validator의 조건 분기를 모두 검증합니다. 변경 규모가 작고(3파일 56줄) 전체 스위트가 회귀 없이 통과해 위험은 낮다고 봅니다. Blocking은 없고, Suggestions S1은 후속 선택 사항, Questions Q1은 리뷰 중 해소됐습니다.

최종 머지 권한은 개발자에게 있습니다.
