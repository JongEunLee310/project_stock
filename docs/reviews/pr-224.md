# PR #224 로컬 리뷰 — chore: docker-compose를 로컬 개발용 단일 구성으로 정리

> 이 리뷰는 value-for-fable:itsvff (Sonnet) 위임으로 작성되었습니다.

## Review Summary

저장소의 docker-compose 구성을 로컬 개발 전용 단일 파일로 되돌리는 정리 PR입니다. 변경 전 `docker-compose.yml`은 스테이징 배포용 구성(이미지 pull, `container_name`, `restart: unless-stopped`, `.env.staging`)이었고, 로컬 개발용으로는 별도의 `docker-compose.local.yml`이 존재했습니다. 이 PR은 스테이징 구성을 저장소 밖으로 내보내기로 결정한 뒤, `docker-compose.yml`을 로컬 개발용(`build: .`, 볼륨 마운트, hot-reload)으로 교체하고 중복이 된 `docker-compose.local.yml`을 삭제합니다. README.md와 `docs/backend-v0.2.md`의 `-f docker-compose.local.yml` 옵션 참조도 함께 갱신했습니다. 코드 변경이 없는 구성·문서 정리이며, 개발자가 직접 작성한 변경입니다.

## Blocking

None.

## Suggestions

**S1. `docs/designs/025-project-readme.md`의 서비스명 기록이 현재 compose와 다릅니다 — 설계 아카이브 갱신을 고려할 수 있습니다.**

설계 문서 025는 compose 서비스명을 `api`(8000), `db`(postgres:16), `redis`(7)로 기록하고 있으나, 현재 `docker-compose.yml`의 서비스명은 `backend`, `postgres`, `redis`입니다. 설계 문서는 구현 의사결정 기록 성격이 강해 사후 수정이 필수는 아니지만, README나 다른 운영 문서와 교차 참조할 때 혼선을 줄 수 있습니다. 현 PR 범위 밖이므로 강제하지 않되, 후속 문서 정리 시 함께 반영하면 좋습니다. 현 범위에서 블로킹 사항은 아닙니다.

**S2. `docker-compose.yml` 변경은 human-gate-policy의 인프라/배포 구성 변경 조건에 해당합니다 — 이 PR은 개발자가 직접 작성했으므로 게이트가 충족된 상태입니다.**

`docs/harness/human-gate-policy.md`는 "Infrastructure or deployment configuration changes"를 Human Gate 조건으로 명시합니다. 이 PR은 Codex가 아닌 개발자가 직접 작성·개시했으므로 해당 조건은 이미 충족된 것으로 판단합니다. 향후 Codex 핸드오프로 compose를 수정하는 경우, 핸드오프 전 Human Gate 취득이 필요합니다.
