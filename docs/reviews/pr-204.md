# PR #204 로컬 리뷰 — fix: 워커 모델 레지스트리·mock 기본 응답 마감 (BE #202·#203)

## Review Summary

PR #201 머지 후 `LLM_PROVIDER=mock` 실 워커 스모크 테스트에서 발견된 결함 두 건을 닫는
PR입니다. 첫째(#202), 도메인 모델이 FK 대상을 문자열로만 참조하는 구조에서 RQ 워커
프로세스의 임포트 그래프에 `users` 모델이 빠져 `LLMAnalysisRun` flush가
`NoReferencedTableError`로 실패했습니다. 전 도메인 모델을 임포트하는 레지스트리
`app/db/models.py`를 신설하고(설계 077 Decision YY) `app/worker/jobs/__init__.py`가 이를
임포트해 모든 잡에 일괄 적용했으며(Decision ZZ), `alembic/env.py`의 기존 18줄 임포트도
레지스트리로 단일화했습니다. 둘째(#203), `DEFAULT_MOCK_RESPONSES`에 `LLMAnalysisResult`
항목이 없어 mock 경로에서 빈 dict가 반환되던 누락을 유효 응답 추가로 마감했습니다.

두 결함 모두 pytest에서는 재현되지 않는 유형입니다. conftest가 전 모델을 임포트해 FK
문제가 가려지고, 테스트는 mock 응답을 직접 주입해 기본 조립을 타지 않기 때문입니다.
회귀 테스트가 이 사각을 겨냥해 추가됐습니다 — 서브프로세스에서 잡 모듈만 임포트한 뒤
metadata의 FK 대상 존재를 검증하는 `test_worker_model_registry.py`, 레지스트리가 전 모델
모듈을 임포트하는지 AST로 고정하는 `test_alembic_metadata.py` 갱신, 기본 mock 응답의
스키마 검증 테스트입니다. 재발 방지 기록으로 FAILURE-002가 동봉됐습니다.

구현은 Codex가 핸드오프 task-140·141 기준으로 수행했고, Protected Files(도메인 모델·
alembic versions·잡 모듈 3종)는 변경되지 않았습니다.

## Suggestions

- **S1. 첫 스모크 실패 때 `job_runs` #1이 `running` 상태로 남았습니다.** FK 오류로
  세션이 롤백된 뒤 `job_run_service.fail`까지 같은 세션에서 연쇄 실패한 결과입니다
  (FAILURE-002 Impact에 기록). 이번 수정으로 원인은 사라졌지만, 잡 실패 기록용 세션을
  분리하거나 rollback 후 기록하는 보강은 워커 안정화 후속으로 남습니다.
- **S2. 새 도메인 모델 추가 시 `app/db/models.py` 갱신 누락 가능성.**
  `test_model_registry_imports_all_domain_models`가 `app/domains/*/model.py` 패턴을
  AST로 대조해 누락을 잡아주므로 현재로선 충분합니다. 다만 `theses/conflict_model.py`처럼
  `model.py` 이름을 벗어나는 모듈은 이 대조에 걸리지 않으니, 비표준 이름의 모델 모듈을
  새로 만들 때는 레지스트리 수동 추가가 필요합니다.
