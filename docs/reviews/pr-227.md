# PR #227 로컬 리뷰 — feat: 종목 lookup API와 등록 검증 (#226)

리뷰어: value-for-fable (Sonnet — VFF 위임)

## Review Summary

FE 실사용 테스트에서 확인된 두 가지 결함(오타 심볼 등록·오염된 표기 저장)을 근본적으로
차단하기 위해, 실시장 데이터 기반 lookup API를 신설하고 `POST /assets` 등록 경로를
서버 검증·보강 방식으로 전환하는 PR입니다.

변경 파일은 19개, 순증 코드량은 +585줄입니다. 구현 구조는 다음과 같습니다.

**신규 capability 추가**: `app/adapters/market/base.py`에 `SymbolLookupResult` frozen
dataclass와 `SymbolLookupProvider` ABC를 추가합니다. 기존 `MarketDataProvider` /
`PriceSeriesProvider` / `IndexQuoteProvider` capability 분리 패턴을 그대로 따릅니다.
구현체로 `MockSymbolLookupProvider`(결정적 카탈로그 11종목)와
`YFinanceSymbolLookupProvider`(Yahoo Finance Search 기반)가 추가되고,
`get_symbol_lookup_provider()` factory 함수가 `MARKET_PROVIDER` 환경 변수에 따라
분기합니다.

**`POST /assets` 계약 변경 (breaking)**: `AssetCreate`가 `symbol`·`market` 2필드만
수신하도록 축소됩니다. `AssetService.register`는 symbol 대문자 정규화 →
중복 검사(400 `ASSET_DUPLICATE` 유지) → lookup provider 정확 일치 검증 →
미실존 422 `ASSET_NOT_IN_MARKET` → provider가 반환한 `name`·`sector`로 보강 후
저장하는 순서로 재작성됩니다.

**`GET /assets/lookup` 신설**: `AssetService.lookup`이 provider 검색 결과 각 항목에
`registered` 플래그(repo `get_by_symbol_market` 기준)를 조합해 반환합니다.
라우터에서 `/lookup` 라우트가 `/{asset_id}` 라우트보다 먼저 선언되어 있어
`lookup`이 int 파싱 422로 빠지는 문제가 없습니다(`assets.py` 72행 vs 143행).

**기존 테스트 영향 정리**: `POST /assets`를 통해 자산을 생성하던 다섯 개 헬퍼 함수
(`test_watchlists.py`, `test_alert_candidates.py`, `test_signals.py` 등)는
`name=f"{symbol} Inc."` 형식을 페이로드에 포함하고 있었습니다. 새 `AssetCreate`가
`name` 필드를 선언하지 않아 Pydantic이 해당 값을 조용히 무시하고, API는 provider
카탈로그의 실제 이름으로 저장합니다. 이에 맞춰 name 단언이 카탈로그 값으로 갱신되었고
테스트는 정상 통과합니다. `test_portfolios.py`, `test_assets.py`,
`test_assets_symbol_detail.py`의 비카탈로그 심볼(`ZZZZ` 등) 등록은 직접 DB 삽입으로
전환하여 API 검증을 우회합니다.

CI는 오케스트레이터 재실행 기준 ruff·mypy·pytest 3종 모두 통과하였습니다.

## Suggestions

**S1. 여러 테스트 파일의 `create_asset` 헬퍼에 무시되는 `name` 필드가 그대로 남아 있습니다.**

`tests/test_watchlists.py`(13행), `tests/test_alert_candidates.py`(29행),
`tests/test_signals.py`(24행)의 local `create_asset` 함수는 여전히
`"name": f"{symbol} Inc."` 필드를 POST 페이로드에 포함합니다.
`tests/test_watchlist_recommendations.py`(307~310행)의 인라인 `client.post` 호출도
마찬가지입니다. 새 `AssetCreate`에 `name` 필드가 없으므로 Pydantic이 이 값을 조용히
무시합니다. 기능상 테스트는 올바르게 통과하지만, 실제로 아무 효과가 없는 필드를 전송하고
있어 헬퍼의 의도를 오독하게 만들 수 있습니다. 해당 헬퍼들을 `{"symbol": symbol,
"market": "NASDAQ"}` 형태로 정리하면 새 계약을 명확히 반영할 수 있습니다. 현재 범위의
핵심 목표와 무관하므로 후속 정리로 처리해도 무방합니다.

**S2. `lookup` 서비스에서 provider 결과 항목마다 개별 DB 쿼리가 실행됩니다.**

`AssetService.lookup`은 provider 반환 결과 N개에 대해 각각
`repo.get_by_symbol_market`을 호출합니다. mock 카탈로그 11개, yfinance max_results=10
규모에서는 문제가 없지만, 이 패턴은 N+1 쿼리 구조입니다. 현재 스케일에서는 Blocking
사안이 아니며 지금 수정할 이유도 없습니다. 단, 향후 카탈로그나 응답 항목 수가 늘어날
경우 `symbol+market` 쌍으로 배치 조회하는 방식으로 개선할 것을 권고합니다.

**S3. `YFinanceSymbolLookupProvider`의 `sector` 키가 실제 Yahoo Finance Search 응답에
존재하는지 실측으로 확인되지 않았습니다.**

`_lookup_result_from_quote`는 `quote.get("sector")`로 sector를 읽습니다. 테스트 픽스처는
monkeypatch로 `"sector": "Technology"` 키를 직접 주입하므로 통과하지만, 실제
`yf.Search` 결과의 `quotes` 항목에 이 키가 포함되는지는 공식 문서나 실측으로 뒷받침되지
않습니다. 설계에서 "sector가 없으면 None" 처리로 명시되어 있고 코드도 그렇게 동작하므로
기능 장애는 아닙니다. 실제 yfinance 환경에서는 sector가 항상 `None`으로 반환될 수 있다는
점을 인지하면 충분합니다. yfinance provider를 실제 환경에서 사용하기 전에
`yf.Search` 응답 구조를 한 번 확인하는 것을 권장합니다.

## Final Recommendation

**머지해도 좋다고 판단합니다.** Blocking 항목이 없습니다.

등록 검증 경로의 정확성을 확인했습니다. `register`는 symbol·market을 먼저 대문자로
정규화하고, `_find_exact_market_symbol`에서 provider를 통해 정확 일치를 검증한 뒤
provider가 반환한 값으로만 저장합니다. 다른 market의 동일 심볼로 우회하는 경로는 없습니다.
`/lookup` 라우트 선언 위치도 `/{asset_id}` 앞에 올바르게 배치되어 있습니다.

핸드오프 Test Requirements 5개 범주(MockSymbolLookupProvider 단위, lookup 엔드포인트,
`POST /assets` 계약, YFinanceSymbolLookupProvider monkeypatch, factory 분기)가 모두
구현되었고, 기존 테스트는 약화 없이 갱신되었습니다. S1은 후속 헬퍼 정리, S2는 스케일 대응
시점 결정, S3는 yfinance 실환경 진입 전 확인 사항으로, 현재 범위에서 머지를 막지 않습니다.

최종 머지 권한은 개발자에게 있습니다.
