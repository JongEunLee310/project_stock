# PR #469 로컬 리뷰 — feat: 에이전트1 일일 브리프 Obsidian 노트·인덱스 (#462)

## Review Summary

일일 리서치 에이전트가 종목별 일일 노트와 일일 인덱스를 Obsidian vault에 남기게 하는 PR입니다. 커밋은
핸드오프와 Codex 구현으로 구성됩니다.

**Part A — writer 확장(#462, 설계 459 §5).** `render_daily_brief_note`는 `DailyBriefContent`를 섹션별 Markdown으로
바꾸고, 인용 번호 `N1`·`P1`을 각주 `[^N1]`·`[^P1]`로, 근거를 각주 정의로 씁니다. 빈 섹션은 생략하고 `stale`
가격에는 "오래된 데이터"를 표시합니다. `render_daily_index`는 종목마다 wikilink와 핵심 요약 한 줄, 실패 사유를
씁니다. 기존 Q&A 노트의 배타적 생성·이름 충돌 접미사·vault 경로 검증 루프는 공용 내부 함수로 뽑혀 세 종류
노트가 함께 쓰며, Q&A 노트 동작은 바뀌지 않았습니다.

**Part B — 에이전트 연결.** `DailyResearchAgent`가 `obsidian_writer`를 받아, 종목 처리 마지막(신호 단계 뒤)에
종목 노트를 쓰고 전 종목 실행이 끝나면 인덱스를 씁니다. 종목 단위 실행은 인덱스를 쓰지 않습니다.
`OSError`·`ValueError`는 `note_failures`로 기록하고 실행을 계속합니다.

이번 리뷰는 사용자 노트 보호(덮어쓰기 없음), 실패 격리, 실제 Obsidian 표시 형식을 축으로 봤습니다.

## Suggestions

**S1. 같은 날 전 종목 재실행 시 `-2` 노트와 인덱스가 생깁니다 — 경미, 설계상 허용.** 리포트는 같은 날
갱신(upsert)되지만 노트는 새 파일만 만들기 때문에, 재실행하면 종목 노트와 인덱스가 `-2`로 하나씩 더
생깁니다. 사용자 노트를 덮어쓰지 않는다는 원칙을 우선한 결과이고 재실행은 드물다고 봤습니다. 실제로
자주 생기면, 에이전트가 만든 파일임을 frontmatter로 확인한 뒤 덮어쓰는 방식을 검토하면 됩니다.

**S2. 인덱스 wikilink가 vault 기준 전체 경로입니다 — 경미, 허용.** `[[stock-agent/daily/AAPL/2026-10-12|AAPL]]`
형식입니다. Obsidian에서 정상으로 열리고, 같은 이름의 노트가 다른 폴더에 있어도 모호하지 않습니다.
