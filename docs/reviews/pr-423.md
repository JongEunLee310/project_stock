# PR #423 로컬 리뷰 — 백엔드 컨벤션 명문화 — docstring 언어·pydocstyle 도입·repository 생략·service 분할 기준 (#420)

## Review Summary

전면 코드 분석(2026-07-24)에서 확인된 암묵적 백엔드 규약을 문서로 고정하는 docs-only PR입니다. 코드 변경은 없으며, `docs/knowledge/backend-conventions.md`를 신설하고 `docs/knowledge/README.md` 인덱스에 포인터를 추가했습니다.

신설 문서는 네 가지 규약을 담습니다. 첫째, 도메인 레이아웃과 `repository.py` 생략 규약(read-only projection·집계 전용 도메인 7개는 service 직접 쿼리). 둘째, service 분할 기준(기본 단일 `service.py`, 관심사 경계가 뚜렷할 때만 `<concern>_service.py`). 셋째, 하위 구성요소 서브디렉터리 배치(`signals/rules/`·`theses/conflicts/`). 넷째, docstring 규약 — 본문 한국어(코드 기호는 영어), 작성 대상 우선순위, Google 형식, `ruff pydocstyle` 점진 도입 순서. 규약은 소급 강제하지 않고 신규 코드부터 적용하며, `news_insights`의 기존 영어 docstring은 점진 이관 대상으로 명시했습니다.

이번 리뷰는 문서 내용이 실제 코드베이스와 일치하는지, 배치 위치가 적절한지를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. docstring 언어 규약과 `news_insights` 기존 영어 docstring의 불일치는 이관으로 흡수 — 현재 범위에서 허용.** 규약을 한국어로 고정했으나 `news_insights/*`에는 영어 docstring이 남아 있습니다. 이관만을 위한 대량 변경은 하지 않고 해당 파일을 손댈 때 점진 이관하도록 문서에 명시했으므로, 지금 시점의 불일치는 의도된 전환 상태입니다. 후속 docstring 작성 이슈에서 함께 정리하면 됩니다.

## Questions

**Q1. `repository.py` 생략 도메인 목록이 현재 코드와 일치하는지 — 리뷰 중 확인해 해소.** 문서가 나열한 7개 도메인(`alert_engine`, `analysis`, `benchmark`, `catalysts`, `dashboard`, `research_coverage`, `asset_events`)이 실제로 `repository.py` 없이 구성돼 있는지 확인했습니다. 앞선 구조 스캔에서 동일 목록이 "service 있음 / repository 없음"으로 확인됐고, 문서 서술과 일치합니다.

## CI Result

문서 전용 변경이라 코드 검증 명령(`ruff`·`mypy`·`pytest`)의 대상이 아닙니다. 리뷰어(Claude Code)가 2026-07-24에 다음을 확인했습니다.

- 변경 파일은 `docs/knowledge/backend-conventions.md`(신설)와 `docs/knowledge/README.md`(인덱스 1줄 추가) 두 건뿐이며, `app/`·`tests/` 코드 변경은 없습니다.
- 문서가 참조하는 경로(`signals/rules/`, `theses/conflicts/`, `docs/harness/design-record-policy.md`, `docs/backend-v0.2.md`)가 실재함을 확인했습니다.

GitHub Actions는 docs-only 변경이라 코드 게이트에 영향이 없습니다.

## Documentation Impact

이 PR 자체가 문서 산출물입니다. `docs/knowledge/backend-conventions.md`가 백엔드 구조·docstring 컨벤션의 정본이 되며, `docs/knowledge/README.md` 인덱스에 등재됐습니다. ADR은 불필요합니다 — 새로운 아키텍처 방향을 선택하는 것이 아니라 이미 코드에 존재하는 관행을 서술하고, 기존 `design-record-policy.md`의 언어 규약과 정합합니다. Failure Record도 불필요합니다.

## Final Recommendation

머지 가능합니다. 문서가 서술한 네 규약이 모두 실제 코드베이스의 관행과 일치함을 항목별로 확인했습니다 — repository 생략 도메인 목록, 서브디렉터리 배치 예시(`signals/rules/`·`theses/conflicts/`), docstring 언어 규약(#420 결정 사항인 한국어와 일치). 코드 변경이 없어 회귀 위험은 없고, Protected Files 변경도 없습니다. 문서 규약이므로 테스트는 대상이 아닙니다. Blocking·Questions는 없거나 해소됐고, Suggestions S1은 후속 docstring 이슈에서 흡수되는 전환 상태입니다.

최종 머지 권한은 개발자에게 있습니다.
