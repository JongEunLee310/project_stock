## Review Summary

이 PR은 PR #292 로컬 리뷰에서 남겼던 후속 세 건(Q1·S1·S2)을 한 라운드로 처리합니다. 설계 문서 `docs/designs/293-294-research-queue-followups.md`가 명시한 범위와 정확히 일치하며, 변경 파일도 핸드오프 스코프(`schema.py`·`service.py`·`docs/api/frontend-api-spec.md`·`docs/designs/266-research-queue-contract.md`·테스트·설계/태스크 문서)로 한정되어 있습니다.

`app/domains/research_queue/schema.py`에는 `ResearchStatus`에 `PENDING_ANALYSIS` 값이 추가됐습니다. `service.py`의 `_derive_status`는 완성도 규칙(`INSUFFICIENT`/`COLLECTING`) 다음, `STALE` 판정 앞에 `last_updated_at is None → PENDING_ANALYSIS` 분기를 삽입해 설계 §2 판정 우선순위 표와 정확히 같은 순서를 구현합니다. `_NEEDS_RESEARCH_STATUSES`에도 `PENDING_ANALYSIS`가 포함되어 needs_research 카운트·필터에 반영됩니다.

기준 시각 단일화는 `list_queue` 진입 시점에 `now = utc_now()`와 `today_start`를 한 번만 계산해 `_derive_status`·`_build_summary`·`_apply_filter`에 인수로 전달하는 방식으로 구현됐습니다. 기존에 `_build_summary`와 `_apply_filter` 내부에서 각각 호출하던 `utc_now()`는 제거됐습니다. `_top_signal_type`의 `min(signal_types)` fallback도 `None` 반환으로 교체되어, 우선순위 목록 외 시그널 타입만 있는 경우 알파벳 최솟값이 노출되지 않습니다.

계약 문서 갱신도 확인했습니다. `docs/api/frontend-api-spec.md`의 `research_status` 값 목록과 `docs/designs/266-research-queue-contract.md` §4.1 판정 표·`needs_research` 필터 매핑 표 모두 `PENDING_ANALYSIS`를 반영하며 순서(`NEEDS_ATTENTION → INSUFFICIENT → COLLECTING → PENDING_ANALYSIS → STALE → ANALYZED`)가 코드·설계·계약 문서 세 곳에서 일치합니다.
