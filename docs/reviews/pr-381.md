# PR #381 로컬 리뷰 — 뉴스 인텔리전스 투자자 동향 계약 (#368)

## Review Summary

뉴스·공시 인텔리전스(에픽 #307) 2차의 투자자 동향으로, `GET /api/v1/news-insights/investor-flows`를 추가합니다. 브랜치는 2차 모델 골격(#380)·#306(#379) 위에 스택돼 있으나 PR base는 dev이며 커밋은 1건입니다. 단일 관심사이므로 Part 분할 없이 이어서 설명합니다.

`service.get_investor_flows`가 `investor_flows` 테이블(2차 골격 seed)을 유형별로 집계하고, 뉴스 감성과 총수급 방향의 정렬 여부를 판단합니다. `schema.py`의 `InvestorFlowsResponse`는 `by_investor_type`[{investor_type·net_value·direction·change}]·`narrative_alignment`{aligned·note}·`availability`{available·fallback}로 구성됩니다. `net_value`는 금액이므로 `Decimal` 타입에 `field_serializer(when_used="json")`로 문자열 직렬화합니다. 라우트는 `market`(필수)·`window`(필수, `^[1-9]\d*[hd]$`)·`topic_id`(선택)를 받고 기존 `get_current_user`·`success` 엔벨로프를 재사용합니다. 데이터 미제공 시장은 값을 추정하지 않고 `availability.fallback`에 ETF·거래량 대체 지표를 명시합니다.

이번 리뷰는 설계 §3.2 계약 일치, 금액 문자열 직렬화, 미제공 시장 처리, 범위 이탈 여부를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. `change` 산식이 설계에 미명시 — 직전 스냅샷 대비 증감률로 구현, 합리적이나 계약 명문화 권장.** 설계 §3.2는 `change` 필드만 정의하고 산식을 명시하지 않았습니다. 구현은 직전 스냅샷 대비 증감률(float)로 계산합니다. 통상적 해석이라 병합을 막지 않으나, FE 연동(project_stock_frontend#264) 전에 "전일 대비"인지 "직전 스냅샷 대비"인지 계약을 확정해 두면 표시 라벨 불일치를 예방할 수 있습니다.

**S2. `market` 필수화 — 시장별 데이터 가용성 차이를 반영한 합리적 결정.** 설계는 `market`을 query로만 두고 필수 여부를 명시하지 않았으나, 구현은 필수(min_length 1, 정규화 upper)로 뒀습니다. 투자자 수급은 시장별 가용성이 달라 market을 필수로 두는 편이 availability 판단에 자연스럽습니다. 계약 확정 시 이 결정을 문서에 반영하면 됩니다.

## Questions
