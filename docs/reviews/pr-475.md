# PR #475 로컬 리뷰 — feat: 지식 정본 knowledge_documents와 지식 청크 인덱싱 (#471)

## Review Summary

공시 섹션 같은 지식 문서의 정본 테이블을 만들고 임베딩 인덱서에 연결하는 PR입니다. 커밋은 설계와
핸드오프, Codex 구현으로 구성됩니다.

**Part A — 정본 모델(설계 445 §2).** `knowledge_documents`는 설계 표의 필드·제약·인덱스를 그대로
따릅니다. `metadata` 컬럼은 `metadata_` 속성으로 매핑하고 기본값은 `{}`입니다. repository는 commit하지 않고
flush만 하므로, 수집 서비스(#472)가 종목 단위로 commit할 수 있습니다.

**Part B — 인덱서(설계 445 §4).** 뉴스 스캔 뒤에 남은 `max_documents` 한도 안에서 지식 문서를 id 순으로
스캔합니다. 해시 비교, 배치 shape 검증, 원천별 삭제 후 upsert 규칙은 뉴스와 같습니다. 삭제·upsert는 이제
(`source_type`, `source_id`) 쌍으로 구분하므로, 뉴스와 지식 문서의 id가 같아도 서로 지우지 않습니다.
뉴스만 있는 경우의 결과는 이전과 같습니다.

이번 리뷰는 뉴스 경로 불변, 원천 간 id 충돌, 마이그레이션 왕복을 축으로 봤습니다.

## Suggestions

**S1. 지식 문서는 청크 수가 많아 한 번의 실행이 커질 수 있습니다 — 경미, #472에서 관찰.** 뉴스는 문서당
청크가 1~2개지만, 10-K 섹션은 문서당 수십 개입니다. 지금 구조는 한 실행의 청크를 모두 메모리에 모은 뒤
한 트랜잭션으로 씁니다(임베딩 요청은 어댑터가 100개씩 나눔). 첫 적재 규모는 약 500개 청크(설계 §4)라
문제가 없을 것으로 봅니다. #472 실측에서 실행 시간을 확인하고, 길면 지식 문서의 문서 한도를 따로 두면 됩니다.

**S2. `list_by_asset`의 정렬 기준을 Codex가 정했습니다 — 경미, 허용.** 유효일 최신순이고, 날짜가 없으면
뒤로 보내며, 같으면 id 역순입니다. 에이전트 2가 "최근 보고서 두 건"을 읽는 용도에 맞습니다.
