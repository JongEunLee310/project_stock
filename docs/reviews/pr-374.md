# PR #374 로컬 리뷰 — 뉴스 인텔리전스 데이터 모델 골격 (#305)

## Review Summary

뉴스·공시 인텔리전스(에픽 #307) 1차 선행 과제로, `Document → Event → Topic → Insight → Evidence` 3층 흐름을 고정하는 신규 도메인 `app/domains/news_insights/`의 모델 계층을 추가합니다. 커밋은 2건입니다 — 모델·enum·마이그레이션·seed 추가(f3e910d 이전)와 CI `mypy .`(전체 451파일) 타입 오류 수정. 라우터·service는 포함하지 않고 모델 계층까지만 다룹니다.

기존 도메인 패턴(`model`/`types`/`repository`/`service`)을 그대로 따르며, 새로 추가된 것은 `types.py`의 enum 11종, `model.py`의 ORM 7종(`source_documents`·`extracted_events`·`event_evidence`·`topic_clusters`·`topic_keywords`·`keyword_relations`·`topic_insights`), 계약 시연용 `seed.py` 헬퍼, autogenerate 등록(`app/db/models.py` 한 줄), alembic revision `006b`입니다. 계약 정본은 설계문서 `docs/designs/307-news-intelligence.md`(§2 enum, §3 테이블)이며, 구현은 이 문서의 필드·제약과 일치합니다.

이번 리뷰는 설계문서 계약과의 일치, 사실/추론 분리 원칙 준수, 범위 이탈 여부를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S0. 초기 CI Typecheck 실패 — 리뷰 중 수정 완료.** 최초 커밋은 검증을 `uv run mypy app`(app 하위 패키지)으로만 돌려, CI가 실행하는 `uv run mypy .`(테스트·마이그레이션 포함 451파일)에서 5건이 걸렸습니다(마이그레이션 헬퍼 반환형 `sa.Column[object]`, 테스트의 `__table__`(FromClause) 속성 접근, `EnumMeta` dict 키). 헬퍼 반환형을 `sa.Column[Any]`로, `__table__` 접근을 `cast(Table, ...)`로, enum 순회를 `type[Enum]` 헬퍼로 정리해 `mypy .` 전체를 통과시켰습니다. 코드 계약(테이블·enum)에는 영향이 없습니다. 후속 핸드오프(#301~#304)의 Verification Commands는 `mypy .`로 명시합니다.

**S1. enum 값이 DB 레벨 제약 없이 String으로 저장됨 — 현재 범위에서 허용, 검증은 상위 계층 예정.** `document_type`·`sentiment_direction`·`evidence_role`·`lifecycle_status`·`category` 등은 `String`으로 저장되고 값 무결성은 애플리케이션 enum에만 의존합니다. 이는 기존 도메인(`decision_logs` 등)과 동일한 방식이며, 잘못된 값 차단은 후속 schema 계층(#301~#304)의 입력 검증 422로 처리하기로 설계문서 와이어 컨벤션에 명시돼 있습니다. 점수 컬럼은 이미 CHECK 0.0~1.0 제약이 있어 무결성 위험이 큰 필드는 보호됩니다. 후속 조치는 불필요합니다.

**S2. `key_evidence`·`risk_points`·`counter_arguments`가 JSON 컬럼 — 골격 단계에서 적절.** `topic_insights`의 구조화 근거·반대 근거를 JSON으로 저장합니다. 1차는 mock 계약 고정이 목적이고 이들 필드의 조회 조건이 없으므로 정규화된 테이블 대신 JSON이 합리적입니다. evidence event ID 참조 무결성 검증은 브리핑·인사이트 조립 계층(#302·#304)에서 subset 검증으로 다루도록 설계문서 §4.3에 예고돼 있습니다.

## Questions

**Q1. PostgreSQL 실DB 마이그레이션 적용은 CI에서 확인 필요.** 로컬 `.env`가 Docker 전용 호스트 `db`를 가리켜 `alembic upgrade head`가 로컬 PostgreSQL에 적용되지 못했습니다. 리뷰 중 SQLite 임시 DB 전체 체인 upgrade와 revision 단위 up/down 테스트로 마이그레이션 정합성은 확인했고, `alembic check`(모델-마이그레이션 차이 없음)도 통과했습니다. PostgreSQL 실적용은 GitHub Actions CI에서 검증되며, 이 기록 작성 시점 CI 결과는 아래 CI Result에 반영합니다.

## Documentation Impact

설계문서 `docs/designs/307-news-intelligence.md`는 이 PR 전 커밋(329a97d)에서 이미 추가돼 계약 정본으로 존재하며, 구현이 문서와 일치하므로 추가 갱신은 불필요합니다. 상태는 이미 `계약 확정(Frozen)`입니다. ADR은 불필요합니다 — 기존 도메인 레이어·와이어 컨벤션을 따르는 신규 테이블 추가이고, 3층 분리 원칙은 에픽 #307에 이미 기록돼 있습니다. Failure Record는 해당 사항이 없습니다.

## Final Recommendation

머지 가능합니다. 설계문서 §2 enum 11종과 §3 테이블 7종이 필드·nullable·제약 수준에서 구현과 일치함을 항목별로 확인했습니다. 사실(documents·events·evidence)과 AI 추론(topics·keywords·relations·insights)의 테이블 분리, `importance_score`와 sentiment의 분리 컬럼, `content_hash` unique·`event_fingerprint` index, `topic_insights`의 `(topic_id, version)` unique(버전 누적), `counter_arguments` non-nullable(반대 근거 의무)이 모두 반영됐습니다. 범위는 모델 계층까지로 지켜졌고 라우터·service는 추가되지 않았습니다. Protected Files 변경은 없으며 `app/db/models.py`는 등록 한 줄만 추가됐습니다. 추가된 테스트는 enum·FK·unique/index 제약·seed 삽입·마이그레이션 up/down을 덮습니다. Blocking은 없고, S0(초기 CI Typecheck 실패)는 리뷰 중 수정돼 CI green으로 해소됐으며, Suggestions(S1·S2)는 후속 계층에서 다뤄질 설계상 허용 사항이고, Questions(Q1)는 CI green(run 29823392498) 확인으로 해소됩니다.
