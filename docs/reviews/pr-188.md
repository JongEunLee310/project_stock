## Review Summary

LLM 데이터 파이프라인 6단계로, 여러 도메인 데이터를 모아 LLM 직전 입력인 `LLMContextBundle`을
조립하는 ContextBuilder를 신설한 PR입니다. 기존 도메인 `app/domains/llm_context/`에
`context_builder.py`와 기본 규칙 상수 `user_rules.py`만 추가했고, 계약(`schema.py`)·기존 소스
도메인·마이그레이션·route는 건드리지 않았습니다(설계 Decision X·Y·Z).

`ContextBuilder`는 `Session`을 받아 자산·가격·포트폴리오·decision-log 리포지토리와 포트폴리오
서비스를 구성하는 읽기 전용 서비스입니다. 4개 메서드가 지침 §11(6단계)와 설계 3.2에 정확히
대응합니다. `build_symbol_context`는 자산 조회로 display_name을 채우고, `PriceBarRepository.
list_recent`로 최대 252 bar를 가져와 5단계 `PriceFeatureBuilder`로 `PriceSnapshot`을 만들며(close는
최신 종가), 보유 포지션이 있으면 `portfolio_context`를, 없으면 `None`을 담습니다. `recent_news`·
`signals`는 빈 리스트로 두고(Core slice, Decision AA), `build_portfolio_context`는 기존
`PortfolioService.get_summary`를 재사용해 `cash_ratio`·`top_holding_weight`·`concentration_risk`로
매핑합니다. `build_recent_decision_context`는 decision-log의 `ticker` 필드로 심볼을 매칭하고,
`build_context_bundle`이 이를 모아 `data_quality`·`output_contract`·`user_rules`까지 채운 번들을
반환합니다.

`Decimal→float` 변환(`_to_float`), 분모 0 가드(`_calculate_unrealized_return`,
`_get_first_portfolio_summary`의 예외 흡수), 소스 결손 시 예외 없는 degradation이 일관되게
구현됐습니다. 설계 Decision X·Y·Z·AA·BB·CC·DD·EE를 모두 따랐고, 반환 타입에 `Dto`를 쓰지 않아
네이밍 정책도 지켰습니다.

## Suggestions

- **S1 · 번들당 `get_summary` 반복 호출**: `build_context_bundle` 한 번에서
  `_get_first_portfolio_summary`(→ `PortfolioService.get_summary`)가 심볼 수 N만큼의
  `_build_position_context` + `build_portfolio_context` + `_portfolio_data_status`로 총 N+2회
  호출됩니다. `get_summary`는 매번 DB 조회와 시세 provider 호출을 수반하므로, 심볼이 늘면 중복
  비용이 커집니다. 이번 범위(수동 소수 심볼)에서는 문제가 아니지만, 6.5/7단계에서 번들 생성 시
  포트폴리오 요약을 1회 계산해 재사용(메모이제이션)하는 것을 권합니다.
- **S2 · `user_intent` 매핑의 KeyError 여지**: `_USER_INTENT_BY_TASK_TYPE[task_type]`는 직접
  인덱싱이라 향후 `LLMTaskType`에 값이 추가되고 매핑이 누락되면 `KeyError`가 납니다. 현재 7종은
  모두 커버돼 문제는 없으나, graceful degradation 원칙(경계에서 예외 회피)에 맞춰 `.get(task_type,
  기본 문구)`로 두면 안전합니다.
- **S3 · 비중 척도 표기**: `cash_ratio`·`top_holding_weight`·`weight`는 내부 요약의 분수 척도
  (예: 0.6)를 그대로 담습니다. 지침 §7 예시는 백분율(18.5)로 표기돼 있어, 7단계에서 번들을 프롬프트로
  변환할 때 척도(분수 vs 백분율)를 명시·통일하는 것을 권합니다. 이번 단계는 내부 척도 일관성을
  유지하는 선택(Decision DD)이라 범위 내 문제는 아닙니다.
- **S4 · `concentration_risk` 버킷**: `exceeds_threshold → high`, `has_sector_concentration →
  medium`, 그 외 `low`의 휴리스틱 매핑입니다. 합리적이나 임계 기준이 문서화되지 않았으므로, 소비
  단계에서 이 라벨의 산출 근거를 함께 노출하면 해석 신뢰도가 올라갑니다.
