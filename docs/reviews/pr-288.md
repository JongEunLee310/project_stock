## Review Summary

이 PR은 `MARKET_PROVIDER=yfinance` 전환 시 `factory.py`에서 `NotImplementedError`로 깨지던 시세·지수·환율 세 경로를 완성하고, 실호출 빈도를 낮추기 위한 Redis TTL 캐시 레이어를 추가합니다.

변경은 네 축으로 구성됩니다. 첫째, `yfinance.py`에 `YFinanceMarketDataProvider`·`YFinanceIndexQuoteProvider`·`YFinanceExchangeRateProvider` 세 클래스를 추가합니다. 모두 심볼 단위로 `Ticker.fast_info`를 조회하고 개별 실패는 로그 후 스킵합니다. 값 변환은 `quote_result_from_fast_info` 등 순수 함수로 분리했습니다. 둘째, `cache.py`를 신규 추가해 `fetch_json_cached` 공통 함수와 세 캐시 래퍼 클래스를 구현합니다. TTL은 설계 확정값(quote·index 60초, fx 300초)이고 Redis 장애 시 loader 직접 호출로 폴백합니다. 셋째, `factory.py`에 yfinance 분기를 추가해 각 provider를 캐시 래퍼로 감싸 반환합니다. mock 분기와 `NotImplementedError` 폴백은 그대로 유지됩니다. 넷째, `tests/test_market_cache.py`를 신규 추가하고 `tests/test_providers.py`를 확장해 순수 함수·캐시·factory 분기를 모두 커버합니다.

**구현 경위:** 최초 커밋(3837b17)은 `_fast_info_value` 내부에서 `fast_info` 객체를 dict처럼 snake_case 키로 조회했습니다. 그러나 실제 yfinance `FastInfo`는 속성 접근(`fast_info.last_price`)을 기본 인터페이스로 제공하고, dict-like `get()` 메서드에는 camelCase 키를 노출합니다. 이 불일치로 실환경에서 모든 심볼 조회가 `None`을 반환해 스킵되는 버그가 발생했습니다. 오케스트레이터가 실 yfinance 스모크 테스트(NVDA·005930 quote, 지수 4종, USD/KRW)를 수행해 이를 발견했고, 1782f38에서 속성 접근을 우선하고 camelCase dict-get을 폴백으로 두는 방식으로 수정됐습니다. 수정 후 동일 스모크 테스트를 통과했습니다. 이 PR의 회귀 테스트(`StubFastInfo`·`test_yfinance_market_provider_skips_individual_symbol_failure`)는 이 계약을 고정합니다.

설계 문서 `docs/designs/230-yfinance-real-providers.md`와 대조 결과, API 계약·`base.py` 시그니처·`mock.py`·소비 서비스 변경이 없으며 스코프 내 Files 절 지정 파일만 변경됐습니다.

## Suggestions

**S1. `fetch_json_cached`에서 JSON 파싱 실패 시 동작이 문서화되지 않았습니다 (`app/adapters/market/cache.py:152-153`)**

`json.loads(raw)` 또는 `_decode_json` 내부에서 예외가 발생하면 외부 `try` 블록(line 148-160)의 `except Exception`에 catch되어 `loader()`를 직접 호출하는 폴백 경로로 떨어집니다. 동작 자체는 올바르지만 이 시나리오가 주석이나 테스트로 명시되어 있지 않습니다. 설계 2절의 "Redis 예외 시 loader 직접 호출" 범위에 JSON 파싱 오류가 포함된다는 점을 WHY 주석 한 줄로 명시해 두면 다음 기여자가 의도를 명확히 이해할 수 있습니다. 현재 범위 내 허용 수준입니다.

**S2. 캐시 hit 시 `as_of`가 저장 시점 값으로 반환됩니다 (`app/adapters/market/cache.py:150-153`)**

캐시 hit 시 `QuoteResult.as_of`는 loader가 실행된 이전 시각(최대 TTL만큼 과거)으로 반환됩니다. 설계 1절에서 "as_of는 조회 시각(UTC)"이라고 명시했지만, 캐시 적중 경우는 별도 언급이 없습니다. TTL이 60초이므로 실용적으로는 허용 범위이고, 소비 서비스들이 as_of를 엄격하게 "현재 시각"으로 단언하지 않는다면 문제가 발생하지 않습니다. 후속 라운드에서 as_of의 의미(캐시 저장 시각 vs 반환 시각)를 설계에 명문화하는 것을 고려할 수 있습니다.

**S3. `_FAST_INFO_DICT_KEYS` 상수가 `_fast_info_value` 함수에서만 사용되는데 모듈 최상위에 선언되어 있습니다 (`app/adapters/market/yfinance.py:298-305`)**

camelCase 폴백 매핑 상수는 `_fast_info_value` 내부에 두어도 의존성 범위를 좁힐 수 있습니다. 다만 상수를 함수 밖에 두는 것이 명시적 계약 문서화 역할도 하므로 현재 위치도 타당합니다. 현재 범위에서 허용되는 수준입니다.
