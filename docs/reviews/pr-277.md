## Suggestions

**S1. `_POINT_COUNTS` 키 타입과 mypy 표현 불일치 — 기능상 무해하나 타입 서술 개선 여지**

`benchmark/service.py`의 `_POINT_COUNTS: dict[str, int]`는 키로 `BenchmarkRange.value` 문자열을 사용합니다(diff 154–159행). `BenchmarkRange.ONE_MONTH.value` 등 enum `.value`를 키로 쓰고 있으므로 dict 리터럴은 완전히 합법이지만, 타입 어노테이션을 `dict[BenchmarkRange, int]`로 선언하고 `range_.value` 대신 `range_`를 직접 키로 쓰면 mypy가 잘못된 키를 컴파일 타임에 잡아 줄 수 있습니다(현재는 `_POINT_COUNTS[range_.value]`에 `.value` 변환이 필요). 동작에 문제는 없으며 후속 실수집 라운드에서 서비스 전체를 정리할 때 함께 개선해도 충분합니다. 심각도: 비차단·가독성/타입 안전성 개선.

**S2. `test_benchmark.py`의 `create_asset` 모듈 함수가 `client` 픽스처 DB를 공유하지 않아 잠재적 경쟁 가능성**

`test_benchmark.py`는 `TestingSessionLocal`을 직접 열어 자산을 생성합니다. `test_valuation.py`·`test_earnings.py`도 동일 패턴입니다. 현재 테스트가 순차 실행되고 각 테스트 함수마다 DB를 초기화하는 `client` 픽스처 구조에서는 문제가 없습니다. 다만 병렬 실행(예: `pytest-xdist`)으로 전환하면 고정 테이블을 공유해 id 충돌이 날 수 있습니다. `test_research_coverage.py` 등 선행 테스트 파일도 동일 패턴을 쓰므로 이 PR 고유 문제는 아닙니다. 심각도: 비차단·후속 고려.

**S3. `EarningsQuarter.operating_margin_percent` 파생 정밀도가 분기마다 다를 수 있음**

`_quarter_from_template`에서 `operating_income / revenue * 100`을 `.quantize(Decimal("0.01"))`로 반올림합니다(diff 413–415행). 현재 2개 템플릿의 값은 모두 소수점 둘째 자리 이내여서 일관성이 있지만, 향후 실수집으로 전환할 때 템플릿의 revenue·operating_income 단위(현재 백만 단위 정수로 보임)와 실수집 값 단위가 다르면 비율 계산이 달라집니다. 이 점을 서비스 주석 또는 설계 문서에 단위 가정으로 명시해 두면 실수집 전환 시 혼동을 줄일 수 있습니다. 심각도: 비차단·실수집 전환 대비.

## Questions

**Q1. `BenchmarkSeries.label`의 고정 문자열(`"NASDAQ 100"`, `"XLK"`)과 실수집 전환 전략**

`BenchmarkService._series`에서 INDEX 시리즈 label을 `"NASDAQ 100"`, SECTOR_ETF를 `"XLK"`로 하드코딩합니다(diff 192–203행). 설계 문서는 label을 "표시명(예: 자산 심볼, NASDAQ 100, 섹터 ETF 심볼)"으로 예시만 제공했습니다. 실수집 전환 라운드에서 섹터→ETF 매핑 테이블을 도입할 때 이 label이 동적으로 결정되어야 한다면, mock 단계의 하드코딩이 FE 컨슈머에게 특정 label을 기대하게 만들 수 있습니다. 현재 범위 안에서는 문제가 없지만, 실수집 라운드 설계 시 label 계약을 심볼 기반 동적 값으로 확정하는 시점에 FE와 함께 정렬이 필요한지 확인을 권장합니다. 심각도: 비차단·실수집 라운드 설계 입력.

**Q2. `eps_surprise_percent` 양·음 혼재 단언이 템플릿 조합에 의존함**

`test_earnings.py`는 `len(_TEMPLATES)` 개 자산을 생성해 모든 템플릿을 순회하고, 수집된 모든 분기에서 surprise 양수·음수가 각각 하나 이상 존재하는지 단언합니다(diff 905–908행). 현재 템플릿 0의 2025Q3(estimate 1.46, 실제 1.41 → surprise 음수)·2025Q2(estimate 1.42, 실제 1.48 → surprise 양수)가 이를 충족합니다. 그러나 두 템플릿 합산을 전제로 하므로 템플릿을 추가할 때 새 템플릿 단독으로도 양·음이 혼재하는지를 별도로 검증하지 않습니다. 현재 2개 템플릿 구조에서는 문제가 없고 이 PR의 범위도 아니지만, 향후 템플릿 추가 시 이 점을 인식할 것을 권장합니다. 심각도: 비차단·정보 공유.
