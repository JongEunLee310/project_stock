# PR #455 로컬 리뷰 — feat: RAG 1차 검색 품질 평가 세트·기준선과 검색 상수 조정 (#444)

## Review Summary

RAG 1차의 검색 품질을 재현 가능하게 측정하는 평가 세트와 스크립트를 추가하고, 그 측정 결과로 검색
상수를 조정하는 PR입니다. 커밋은 평가 세트와 핸드오프(orchestrator), 평가 스크립트(Codex), 상수
조정(Codex), 결과 문서(orchestrator)로 구성됩니다.

**Part A — 평가 세트와 스크립트(#444).** `docs/experiments/rag-eval-set.json`은 18문항이며, 관련
근거를 질문별 제목 정규식으로 정의해 라벨을 기계적으로 다시 만들 수 있습니다.
`scripts/evaluate_rag_retrieval.py`는 서비스와 같은 검색 경로(`get_embedder`, `get_vector_store`,
`ChunkFilter`, `CANDIDATE_K`, `postprocess_hits`)를 쓰고, 질문마다 후보를 한 번만 검색한 뒤 하한별로
후처리를 다시 적용해 sweep 표를 만듭니다. 지표 계산은 순수 함수로 분리돼 단위 테스트가 있습니다.
`--with-llm`은 `reference_now`를 주입한 `ResearchQAService.ask`로 부족 판정 비율과 응답 시간을 잽니다.

**Part B — 상수 조정(측정 근거, 설계 438 §5.2).** `MIN_SCORE`를 0.3에서 0.5로, `TITLE_ONLY_WEIGHT`를
0.8에서 1.0으로 바꿨습니다. `postprocess_hits(min_score=None)`이 호출 시점에 `MIN_SCORE`를 읽도록 고쳐,
상수를 바꾼 실험이 서비스 경로에 그대로 반영되게 했습니다. 평가 스크립트의 같은 패턴도 고쳤습니다.

이번 리뷰는 측정 방법의 타당성, 조정 근거의 충분성, 서비스 동작 변화의 범위를 축으로 봤습니다.

## Suggestions

**S1. 정규식 라벨이라 precision이 실제보다 낮게 나올 수 있습니다 — 경미, 문서에 명시됨.** 제목이
정규식에 걸리지 않는 관련 기사(예: 실적 기사인데 "earnings"·"revenue"·"quarter"가 없는 제목)는
비관련으로 집계됩니다. 상대 비교(설정 간 차이)에는 영향이 작지만 절대값으로 읽으면 안 됩니다. 결과
문서에 이 한계를 적어 두었습니다. 2차에서 세트를 넓힐 때 일부 질문은 원문 id를 직접 라벨링하면
정확도가 올라갑니다.

**S2. 평가 세트 18문항은 결론을 내리기에 작습니다 — 경미, 현재 결정에는 충분.** hit@8 한 칸이
1/14(0.071)라 작은 변화도 크게 보입니다. 이번 결정(가중치 1.0, 하한 0.5)은 모든 지표가 같은 방향으로
움직였고 긍정 지표 손실이 없어 위험이 낮습니다. 교차언어 개선책(결과 문서 §결론 3)을 비교할 때는
문항을 늘려야 합니다.

**S3. 첫 요청 콜드 스타트(106초) — 운영 확인 필요.** Ollama가 유휴 시간 뒤 모델을 내렸다가 다시 올리는
것으로 보입니다. `OLLAMA_KEEP_ALIVE`를 늘리거나 임베딩 job(매시)이 모델을 깨워 두는 효과가 있는지
로컬 운영에서 확인하면 됩니다. FE 타임아웃(#308)에는 이미 넉넉한 값을 권했습니다.

## Questions

**Q1. 조정한 상수가 실제 서비스 경로에 반영됐는가 — 리뷰 중 확인해 해소했습니다.** 첫 LLM 측정은
모듈 상수를 바꿔 끼워 실행했는데, `postprocess_hits`의 기본 인자가 정의 시점에 고정돼 서비스 경로는
0.3으로 돌았습니다. 이 문제를 이번 PR에서 고쳤고, 최종 수치는 상수를 코드에 반영한 상태에서 다시
측정한 값입니다(`rag-eval-baseline-2026-10-12-raw.md`의 머리 `min_score 0.500`, LLM 부정 4/4 부족
판정, 긍정 부족 판정 4/14).

## Final Recommendation

머지 가능합니다. 평가 스크립트가 서비스와 같은 검색 경로를 쓰는지, 하한 sweep이 같은 후보에서 후처리만
다시 적용하는지, 상수 변경이 서비스 기본 호출에 반영되는지(monkeypatch 테스트 포함)를 확인했습니다.
서비스 동작 변화는 근거 선별 기준 두 값뿐이며, 측정상 긍정 지표 손실 없이 개선됐습니다. protected
파일 변경은 없습니다. Blocking은 없고 S1~S3는 후속 참고 사항입니다. Q1은 해소했습니다.
