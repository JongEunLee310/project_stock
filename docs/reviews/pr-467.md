# PR #467 로컬 리뷰 — feat: 에이전트1 일일 브리프 저장 모델(research_reports 확장)과 ADR-020 (#460)

## Review Summary

작업형 에이전트 에픽 #459의 첫 PR입니다. 커밋은 ADR-020과 설계 459(orchestrator), 핸드오프, Codex 구현으로
구성됩니다.

**Part A — 결정과 설계(ADR-020, 설계 459).** ADR-020은 네 작업형 에이전트를 고정 워크플로로 만들고 공통
경계를 정합니다. 산출물만 쓰고, 수치는 DB 값을 그대로 쓰고, 인용을 검증하고, 매수·매도를 권유하지 않고,
대상 단위로 실패를 격리합니다. 같은 ADR이 기존 관심종목 분석 흐름(설계 019)을 에이전트 1로 대체하는
매핑을 기록합니다. 기사별 요약은 없애고, 영향도·감성은 종합 호출에서 함께 판정해 `HighImpactNewsRule`을
유지하고, 가설 충돌은 에이전트 3으로 넘깁니다. 설계 459는 종목별 11단계 워크플로와 LLM 계약, 산출물,
트리거 전환을 스켈레톤으로 확정합니다.

**Part B — 저장 모델(#460, 설계 459 §2).** `research_reports`에 `report_type`(기본 `ARTICLE`, Python
기본값과 `server_default` 모두), `brief_date`, `content`(JSON)를 추가하고, `ReportType` enum을 두었습니다.
부분 unique 인덱스 `uq_research_reports_daily_brief`는 `report_type = 'DAILY_BRIEF'`인 행에만 (`asset_id`,
`brief_date`) 유일성을 겁니다. `upsert_daily_brief`는 방언별 `insert ... on_conflict_do_update`에 같은 부분
인덱스 조건(`index_where`)을 주어 원자적으로 갱신하고, `flush`까지만 합니다. `get_latest_daily_brief`는
`DAILY_BRIEF`만 대상으로 최신 행을 돌려줍니다.

이번 리뷰는 기존 리포트 소비처(리포트 API, 리서치 큐)의 무변경, 부분 인덱스의 방언별 동작, upsert의
원자성을 축으로 봤습니다.

## Suggestions

**S1. `get_latest_daily_brief`가 `created_at` 기준입니다 — 경미, #461에서 사용 방식 확인.** 같은 날 다시
실행해 브리프를 갱신하면 `created_at`은 그대로이고 `updated_at`만 바뀝니다. 설계 459 §3의 "직전 브리프
이후 새 소식" 기간 계산은 브리프를 만든 시점을 기준으로 해야 같은 날 재실행에서도 기간이 일관되므로,
지금 기준이 맞다고 봅니다. #461에서 기간 시작을 `created_at`과 `updated_at` 중 무엇으로 할지 명시하면
됩니다.

**S2. ADR-020은 Proposed입니다 — 확정 방식 결정 필요.** ADR-019처럼 이 PR 머지를 승인으로 볼지 정해
주시면 Accepted로 바꾸겠습니다(Q1).
