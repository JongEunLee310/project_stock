# PR #386 로컬 리뷰 — news-insights 테스트 시계 고정으로 날짜 의존 실패 해소

## Review Summary

날짜 경과만으로 `tests/test_news_insights.py` 3건이 동시에 깨져 dev 대상 모든 백엔드 PR의 CI가 막힌 상황을 해소한 PR입니다. 단일 커밋(`뉴스 인사이트 테스트 시계를 고정한다`)입니다.

원인은 시간 축의 이원화입니다. 테스트는 `SEEDED_AT = datetime(2026, 7, 21, 10, tzinfo=UTC)`로 데이터를 고정해 심는 반면, 서비스는 요청 시점의 `datetime.now(UTC)`로 `as_of`를 잡아 24시간 창을 적용합니다(`repository.py`의 집계는 `detected_at >= start AND < end`). 시드는 멈춰 있고 서비스 시계만 흐르므로 실행 날짜가 시드에서 멀어지면 같은 코드·같은 데이터로도 결과가 달라집니다. 2026-07-23에 시드 이벤트·토픽이 창 밖으로 밀리면서 overview 집계가 0이 됐고 topic map·calendar도 함께 어긋났습니다. 07-22까지 통과했던 것(PR #384 CI green)이 이 해석을 뒷받침합니다.

수정은 시계 주입 지점을 하나 만드는 방식입니다. `app/domains/news_insights/clock.py`에 `utcnow()` 한 함수를 두고(운영에서는 그대로 `datetime.now(UTC)` 반환), `service.py`의 현재 시각 획득 6곳을 이 함수 호출로 통일했습니다. `as_of or utcnow()` 형태를 유지해 기존 인자 우선순위는 그대로입니다. 테스트는 autouse fixture(`freeze_news_insights_clock`)로 `app.domains.news_insights.service.utcnow`를 `SEEDED_AT`으로 고정하고, 캘린더 입력도 같은 기준으로 생성합니다. 실패 기록 `docs/failures/FAILURE-004-news-insights-test-clock-drift.md`를 함께 남겼습니다.

이번 리뷰는 운영 동작 불변 여부, 단언 완화 여부, 시계 고정의 실효성(날짜 드리프트 상태에서의 통과), 잔여 실시간 의존을 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 시계 주입이 news-insights 도메인에 한정 — 이번 범위에서 타당, 확장 여지.** `clock.py`는 news-insights 도메인 안에 있고 다른 도메인은 여전히 `datetime.now(UTC)`를 직접 호출합니다. 이번 결함이 이 도메인에서만 드러났으므로 범위를 좁게 잡은 판단이 맞습니다. 다른 도메인에서 같은 증상이 나오면 이 패턴을 공용 위치로 올리면 됩니다.

**S2. `seed.py`의 `now` 인자는 그대로 유지 — 의도된 선택.** 시드는 이미 `now` 인자로 주입 가능하므로 손대지 않았습니다. 시드 시각과 조회 시계를 각각 다른 경로로 주입하는 구조지만, 테스트가 둘 다 `SEEDED_AT`으로 맞추므로 축이 하나로 정렬됩니다.

## Questions

**Q1. 시계 고정이 실제로 날짜에 독립인가.** 리뷰어가 재현 조건 그대로 확인했습니다. 실제 시각이 2026-07-23 01:46 UTC로 `SEEDED_AT`(07-21 10:00)보다 2일 이상 앞선 상태에서, 직전까지 실패하던 3건(overview·calendar·topic map)이 모두 통과합니다. 도메인과 테스트에 남은 실시간 `datetime.now(` 호출이 없음도 확인했습니다(`service.py`·`repository.py`·엔드포인트·테스트 전부 0건).

**Q2. 단언을 느슨하게 만들어 통과시킨 것은 아닌가.** 테스트 diff에서 단언 변경은 한 줄뿐이며, `assert data["as_of"].endswith("Z")`가 `assert data["as_of"] == "2026-07-21T10:00:00Z"`로 **강화**됐습니다. 범위 완화나 단언 삭제는 없습니다.

## Final Recommendation

머지 가능합니다. 운영 경로는 불변입니다(`utcnow()`가 `datetime.now(UTC)`를 그대로 반환, API 응답 계약·집계 로직 무변경). 시계 고정은 실효가 확인됐고(드리프트 상태에서 3건 통과), 단언은 완화가 아니라 강화됐으며, 새 의존성 없이 pytest monkeypatch만 사용합니다.

범위는 지켜졌습니다. 서비스·리포지토리의 집계 로직, window 기본값, seed 데이터 값은 건드리지 않았습니다. Protected Files는 없으며 diff는 `clock.py` 신설·`service.py`의 호출 교체·테스트 fixture·실패 기록에 한정됩니다. 이 PR이 머지되면 dev가 다시 green이 되고, 대기 중인 PR #385(pre-pr-check 훅 가드 수정)도 재실행으로 통과할 수 있습니다.

Blocking은 없습니다. S1·S2는 범위 판단 사항으로 병합을 막지 않으며, Q1·Q2는 리뷰 중 직접 확인해 해소했습니다.
