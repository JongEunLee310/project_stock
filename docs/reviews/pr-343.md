# PR #343 로컬 리뷰 — fix: 알림 지표 데이터 부재를 안정 상태와 구분해 unavailable로 처리 (#341)

## Review Summary

PR #338(이슈 #336) 로컬 리뷰에서 S2로 제기한 사항의 후속입니다. 커밋은 두 건이며 핸드오프
문서(`.codex/tasks/task-205-alert-metric-unavailable.md`) 추가와 구현으로 나뉩니다.

파생 지표(`NEWS_RISK`·`THEME_HEAT`·`AI_JUDGMENT_CHANGED`)는 시그널 스냅샷에서 값을
끌어오는데, `_derive_signal_metrics`가 `signal_type=None`에도 `LOW`·`NEUTRAL`·`STABLE`을
돌려주기 때문에 스냅샷이 아예 없는 자산과 실제로 조용한 자산이 같아졌습니다. 운영 중 규칙이
발동하지 않을 때 데이터가 없어서인지 조건을 만족하지 않아서인지 가릴 방법이 없었습니다.

구현은 새 표현 수단을 만들지 않고 기존 경로에 연결했습니다.
`app/domains/alert_engine/snapshot_provider.py`의 `_aggregate_derived_metric`이 `latest`가
`None`인 자산을 집계 대상에서 걸러내고, 남는 자산이 없으면 `None`을 돌려줍니다. 반환 타입은
`_MetricReading | None`으로 바뀌었습니다. `MetricSnapshotProvider.get_snapshot`은
`_read_metric`이 `None`이면 해당 지표를 `values`에 넣지 않고, `AlertEvaluator`의
`_evaluate_condition`은 `metric not in snapshot.values`를 이미 `unavailable_metric`으로
분류합니다. 그래서 호출부와 `MetricSnapshot` 구조는 손대지 않았고, 프로덕션 코드 변경은 5행에
그칩니다.

리뷰는 세 축으로 봤습니다. 값 미제공 판정이 의도한 경우에만 발생하는지, 기존 집계 규칙
(전이 선택과 tie-break, 최고 심각도 선택)이 필터링 이후에도 보존되는지, 그리고 이번 변경이
후속 이슈 #340의 범위를 침범하지 않는지입니다.

## Suggestions

**S1. 일부 자산만 스냅샷이 없을 때의 취급이 조용히 바뀝니다 — 의도된 개선이며 문서화만
권합니다.** 이전에는 스냅샷 없는 자산이 기본값으로 집계에 참여해 최고 심각도를 끌어내릴 수
있었고, 이제는 아예 빠집니다. 이슈 #341의 범위에 "일부 자산에만 스냅샷이 있는 경우의 취급
기준 확정"이 포함돼 있으므로 요구된 변경이 맞습니다. 다만 운영자 입장에서는 같은 규칙의
집계 대상 수가 날마다 달라질 수 있다는 뜻이므로, 설계 문서
`docs/designs/alert-rule-event-unified.md` §5에 한 줄로 남겨두면 나중에 근거를 되짚기
쉽습니다. 병합을 막지 않습니다.

## Questions

**Q1. 값 미제공과 대상 부재가 결과에서 같게 보입니다.** `_target_asset_ids`가 `None`을
돌려주는 경우(대상 워치리스트가 비었거나 소유자가 다름)와 이번에 추가된 스냅샷 전무는 모두
`unavailable_metric`으로 귀결됩니다. 리뷰 중 확인한 결과 evaluator는 두 경우를 구분할 정보를
받지 않으므로 현재 계약에서는 같은 취급이 맞습니다. 실제 운영에서 둘을 갈라 봐야 할 필요가
생기면 그때 `MetricSnapshot`에 사유를 실어야 하며, 지금 단계에서 선제적으로 넣을 이유는
없다고 판단합니다. 이 PR의 병합 판단에는 영향이 없습니다.

이슈 #341의 완료 조건을 항목별로 확인했습니다. 스냅샷이 전혀 없는 대상은
`unavailable_metrics`로 구분되고(테스트에서 `("AI_JUDGMENT_CHANGED", "NEWS_RISK",
"THEME_HEAT")` 단언), 실제 안정 상태인 대상은 값이 채워진 채 미발동으로 남으며, 두 경우가
서로 다른 테스트로 갈라져 단언됩니다. 비포함으로 명시한 매핑 표와 미지의 `signal_type`
기본값 정책은 diff에 없습니다.

집계 규칙 보존도 확인했습니다. 필터는 `states` 구성 시점에 적용되고 그 뒤의 전이 선택,
tie-break, 최고 심각도 선택 로직은 변경되지 않았습니다. 빈 리스트에서 `max()`가 호출되지
않도록 `if not states: return None`이 선행합니다.

범위가 지켜졌습니다. 프로덕션 코드 변경은 단일 파일 5행이고, 리뷰 S1에서 제기한 다자산
current·previous 불일치(이슈 #340)는 손대지 않아 선행 결정을 기다리는 상태가 유지됩니다.
Protected Files 변경은 없습니다. `evaluator.py`와 `types.py`는 diff에 없습니다.

추가된 테스트는 집계 함수 단위(스냅샷 없는 자산 제외, 전원 부재 시 `None`)와 provider·
evaluator 통합 단위(값 미제공 분류, 실제 안정 상태 유지)를 함께 덮습니다. 기존 테스트 세
건은 반환 타입이 Optional로 바뀌면서 `assert reading is not None`을 앞세우도록 조정됐고
단언 내용은 보존됐습니다.

Blocking은 없습니다. Suggestions S1은 문서 한 줄 보완 제안이고 Questions Q1은 리뷰 중
해소했으므로, 둘 다 병합을 막지 않습니다.
