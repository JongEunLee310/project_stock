# PR #488 로컬 리뷰 — feat: 가설 점검 저장 모델과 에이전트용 AlertEvent 확장 (#485)

## Review Summary

에이전트 3(투자 가설 감시)의 저장 기반을 만드는 PR입니다. 커밋은 ADR-021·설계·핸드오프와 Codex 구현으로
구성됩니다.

**Part A — ADR-021(Proposed)과 설계 465.** 판단 기록은 사용자 개인 데이터입니다. 그런데 신호와 리포트는
종목 단위로 모든 사용자에게 공유되므로, 가설 점검 결과는 사용자별 테이블에 저장하고 알림은 사용자별
`AlertEvent`로 보낸다고 정했습니다. 에이전트는 판단 기록을 바꾸지 않고, 사용자 자유 텍스트는 마스킹을
거칩니다.

**Part B — 구현.** `thesis_checks`는 unique (`decision_id`, `check_date`)로 같은 날 중복 점검을 막습니다.
`alert_events.rule_id`는 nullable이 되고 `source`(server default `RULE`)가 생겼습니다. 규칙 엔진은
`source=RULE`을 명시합니다. `create_agent_event`는 `begin_nested` 안에서 이벤트와 `APP` 전달 기록을 만듭니다.
같은 (`user_id`, `dedup_key`)가 이미 있으면 None을 돌려주고 바깥 트랜잭션은 유지합니다. 규칙 엔진의
중복 처리 방식과 같습니다. downgrade는 규칙 없는 이벤트와 그 전달 기록을 지운 뒤 not null로 되돌립니다.

이번 리뷰는 기존 알림 경로 불변, 사용자 간 격리, 마이그레이션 안전성을 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. `/alert-events` 응답 계약이 바뀝니다 — FE #309로 대응.** `rule_id`가 nullable이 되고 `source`가
추가됩니다. FE는 `ruleId`를 "규칙 #N"으로 그리므로(`AlertDetail`, `AlertHistoryPanel`), FE가 반영되기 전에
에이전트 이벤트가 생기면 "규칙 #null"로 보입니다. 에이전트 이벤트는 #486부터 생성되므로, #486 머지 전후로
FE #309를 처리하면 됩니다.

**S2. downgrade는 에이전트 이벤트를 삭제합니다 — 경미, 의도된 동작.** not null 제약으로 되돌리려면 피할 수
없습니다. 이유가 마이그레이션에 주석으로 남아 있습니다.

## Questions

**Q1. ADR-021을 승인하는가 — 개발자 확인 요청.** 머지를 승인으로 볼지 정해 주세요. 핵심 결정은 세
가지입니다. 사용자 데이터에서 나온 에이전트 산출물은 사용자별로 저장합니다. 에이전트 알림은 규칙 없는
`AlertEvent`로 보냅니다. 에이전트는 판단 기록을 바꾸지 않습니다. 같은 패턴은 이후 사용자 데이터를 입력으로
쓰는 에이전트에도 적용됩니다.
