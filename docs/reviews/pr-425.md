# PR #425 로컬 리뷰 — 백엔드 스킬 활성화 — fastapi-patterns·python-testing·api-design 배선 (Claude+Codex) (#424)

## Review Summary

커밋돼 있으나 `settings.local.json`에서 전부 `off`로 꺼져 있던 스킬 중 백엔드 3개를 활성화해 구현·리뷰의 참조 근거로 배선하는 harness 설정 PR입니다. 애플리케이션 코드(`app/`) 변경은 없습니다. 커밋은 두 건으로, 배선(`chore`)과 정책 정정(`docs`)이 분리돼 있습니다.

두 소비자를 각각 배선했습니다. Claude Code는 `.claude/settings.json`의 `skillOverrides`에 `fastapi-patterns`·`python-testing`·`api-design`을 `on`으로, 나머지 3개를 `off`로 명시했습니다. Codex는 자동 발견 메커니즘이 없으므로 `.codex/instructions.md`에 세 스킬의 `SKILL.md` 경로를 참조로 배선했습니다. 정책 정합으로 `docs/harness/skill-usage-policy.md`가 템플릿의 "커밋 금지" 규정과 파생 프로젝트의 스킬 사용을 구분하도록 정정됐고, `docs/agent/skill-policy.md`가 백엔드 3개를 reference 허용으로 명시했으며, `docs/knowledge/workflow.md`에 활성화 사실이 기록됐습니다. 개인·머신 전용 파일인 `.claude/settings.local.json`은 gitignore 대상이라 커밋에 포함되지 않았습니다.

이번 리뷰는 스킬 선정의 타당성, 두 에이전트 배선의 정확성, 설정 파일 무결성을 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. Codex 배선의 실효는 핸드오프 프롬프트가 instructions.md를 읽도록 지시하는 것에 의존 — 현재 워크플로와 일관, 허용.** Codex는 스킬을 자동 로드하지 않고 `.codex/instructions.md`의 참조를 통해서만 인지합니다. 이는 기존 핸드오프 실행 방식(`codex exec` 프롬프트가 `.codex/instructions.md`·`AGENTS.md`·핸드오프를 읽도록 지시)과 정확히 일치하므로 추가 배선은 불필요합니다. 이후 핸드오프도 instructions.md를 읽도록 유지하면 됩니다.

## Questions

**Q1. 활성화가 Claude Code 세션에 실제로 반영되는지 — 리뷰 중 확인해 해소.** `skillOverrides`를 켠 뒤 `fastapi-patterns`·`python-testing`·`api-design`이 이 세션의 invocable 스킬 목록에 실제로 노출됨을 확인했습니다. 설정 플래그가 로딩까지 이어짐이 검증됐습니다.

## CI Result

harness 설정·문서 변경이라 애플리케이션 코드 게이트(`ruff`·`mypy`·`pytest`)의 대상이 아닙니다. 리뷰어(Claude Code)가 2026-07-24에 다음을 확인했습니다.

- `.claude/settings.json`·`.claude/settings.local.json` — `python3 -c json.load` 파싱 통과(둘 다 유효 JSON).
- `skillOverrides` 최종값 — 백엔드 3개 `on`, 나머지 3개 `off`로 의도와 일치.
- `.codex/instructions.md`가 참조하는 3개 `SKILL.md` 경로 모두 실재.
- 변경 파일은 `.claude/settings.json`·`.codex/instructions.md`·`docs/agent/skill-policy.md`·`docs/harness/skill-usage-policy.md`·`docs/knowledge/workflow.md` 5건이며 `app/`·`tests/` 변경 없음.

## Documentation Impact

이 PR은 문서·설정이 산출물입니다. `docs/agent/skill-policy.md`가 활성 스킬의 정본 상태가 되며, `docs/harness/skill-usage-policy.md`의 템플릿/프로젝트 구분과 `docs/knowledge/workflow.md`의 Skill Usage 항목이 이를 뒷받침합니다. ADR은 불필요합니다 — 새 아키텍처 방향이 아니라 이미 커밋된 스킬의 활성화 스위치를 켜는 설정 변경이고, 자율 워크플로를 도입하지 않아 human gate·autonomy 수준에 영향이 없습니다. Failure Record도 불필요합니다.

## Final Recommendation

머지 가능합니다. 스킬 선정은 프로젝트 성격에 부합합니다 — `fastapi-patterns`·`python-testing`·`api-design`은 Python/FastAPI 백엔드에 직접 관련되고, 제외한 `coding-standards`(프론트 위주)와 `autonomous-*`(정책 제약)는 근거와 함께 `off` 유지됩니다. 두 에이전트 배선이 각 로딩 메커니즘에 맞게 정확합니다 — Claude Code는 `skillOverrides`(세션 노출 확인됨), Codex는 instructions.md 참조(경로 실재 확인됨). 설정 파일은 유효 JSON이고 개인 파일은 커밋에서 제외됐습니다. Protected Files(`.codex/instructions.md`·`docs/harness/`) 변경은 사용자의 명시적 요청에 따른 것으로, 스킬 활성화라는 이번 작업 범위에 필수적입니다. Blocking은 없고, Suggestions S1은 현행 워크플로와 일관되며, Questions Q1은 리뷰 중 해소됐습니다.

최종 머지 권한은 개발자에게 있습니다.
