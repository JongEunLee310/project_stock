## Review Summary

watchlist 변화(1D) 스파크라인을 위해 `range=1D` + 15분 간격 인트라데이 경로를
추가하는 PR입니다. `PriceSeriesProvider`에 `get_intraday_bars` 추상 메서드를 추가하고
yfinance(`period="1d", interval="15m", auto_adjust=True`)·mock 구현을 제공하며,
`PriceSeriesService`에 `_RANGE_INTERVALS` 고정 매핑(`1D → 15m`, 나머지 `1d`)을
도입합니다. 설계 문서(`docs/designs/239-watchlist-1d-intraday.md`)의 Decisions
1~5를 정확히 따릅니다.

핵심 확인 사항:

- 기존 일봉 경로 보존 — `get_series`의 interval 파라미터가 `str | None`으로 바뀌고
  range로부터 파생되지만, 명시 interval이 파생값과 다르면 기존과 동일하게
  `INVALID_PRICE_INTERVAL`(400)을 반환합니다. 1M/3M/6M/1Y 경로의 `_to_bar` 반환은
  `"YYYY-MM-DD"` 형식이 유지되고 기존 테스트가 모두 통과합니다.
- 15m 바의 `date`는 `timestamp.isoformat()` 전체 datetime 문자열입니다.
  `stock_price_bars.timestamp`가 `DateTime(timezone=True)`라서 UTC 오프셋이
  포함됩니다. FE 스파크라인은 `close`만 사용하므로 소비자 영향이 없습니다.
- DB 마이그레이션 없음 — `interval` 컬럼과
  `uq_price_bars_symbol_market_interval_ts` 제약이 기존재하며, 15m 바는
  `interval="15m"`로 저장되어 일봉과 충돌하지 않습니다.
- 엔드포인트는 `sparkline_range` Literal에 `"1D"`만 추가되어 미지원 값은 기존대로
  FastAPI 검증(422)에 걸립니다.
- 테스트 — provider 모킹으로 yfinance 실호출 없이 인자(`period`, `interval`)를
  검증하고, `_to_bar` 형식 분기·sparkline interval 파생·통합 경로(200/422)를
  포괄합니다. 픽스처 range·interval 리터럴에 출처 주석이 있습니다.

검증: `uv run ruff check .` / `uv run mypy .`(332 files) / `uv run pytest`(641 passed)
모두 오케스트레이터가 독립 재실행으로 확인했습니다.
