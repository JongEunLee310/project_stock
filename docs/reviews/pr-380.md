# PR #380 로컬 리뷰 — 뉴스 인텔리전스 2차 데이터 모델 골격 (#307)

## Review Summary

뉴스·공시 인텔리전스(에픽 #307) 2차의 데이터 골격으로, #368·#369·#370 엔드포인트의 공통 선행입니다. 브랜치는 #306(#379) 위에 스택돼 있으나 PR base는 dev이며 커밋은 1건입니다. 이 태스크는 모델 계층까지만 다루고 라우터·service는 포함하지 않습니다.

`types.py`에 enum 5종(`MarketEventKind`·`ValuationBurden`·`AgentStage`·`AgentRunStatus`·`FlowDirection`)을 추가하고, `model.py`에 테이블 6종(`investor_flows`·`topic_symbol_sensitivity`·`market_events`·`market_event_topics`·`agent_runs`·`agent_run_stages`)을 추가했습니다. 설계 §2.3이 캘린더-토픽 연결을 조인 또는 파생 중 택일로 열어뒀는데, Codex는 `market_event_topics` 조인 테이블을 채택했습니다. `investor_flows.net_value`는 금액이므로 Decimal 컬럼이고, 점수 컬럼은 1차와 동일하게 `_score_constraint`로 0.0~1.0 CHECK를 겁니다. `topic_symbol_sensitivity`는 `(topic_id, symbol)` unique이며 exposure_score와 impact_direction을 분리 컬럼으로 둡니다. alembic revision `006c`는 1차 head `006b` 위에 스택됩니다. seed는 1차 토픽·종목과 연결된 2차 mock을 삽입합니다.

이번 리뷰는 설계 §1·§2 계약 일치, 마이그레이션 스택·단일 head, 범위 이탈 여부를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. `market_event_topics` 조인 테이블 채택 — 설계가 택일로 허용한 범위.** 설계 §2.3은 캘린더-토픽 연결을 조인 테이블 또는 `related_topic_ids` 파생 중 선택하도록 열어뒀고, Codex는 조인 테이블을 택했습니다. 다대다 연결을 정규화해 표현하는 합리적 선택이며 PR 본문에 명시돼 있습니다. #370 캘린더 엔드포인트에서 이 테이블로 `related_topic_ids`를 조립하면 됩니다. 후속 조치는 불필요합니다.

**S2. `portfolio_weight`·`current_signal` 미저장 확인 — 설계 의도대로 조회 시 조인.** `topic_symbol_sensitivity`에 두 필드를 저장하지 않았습니다. 이는 중복 저장을 피하고 portfolios·signals 도메인에서 조인하려는 설계 §2.2 의도와 일치하며, 실제 조인은 #369 엔드포인트 태스크의 몫입니다.
