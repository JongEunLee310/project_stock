## Review Summary

`GET /stocks/{symbol}/prices`의 range에 1W(30m·65봉)·5Y(1wk·260봉)를 추가한
PR입니다. 직전 5m 전환(#316)과 같은 매핑 확장 구조를 따릅니다.

- `_RANGE_COUNTS`·`_RANGE_INTERVALS` 매핑이 이슈 명세와 일치합니다 (1W=30m·65,
  5Y=1wk·260).
- yfinance는 intraday interval별 period 매핑(`5m→1d`, `30m→5d`)과
  5Y `period="5y", interval="1wk"` 조합을 사용합니다 — 두 조합 모두 yfinance
  표준 지원 범위이며, 파라미터 조합은 FakeTicker 단언 테스트로 고정됩니다.
- `_to_bar`의 date 분기가 `1wk`를 캘린더 날짜 계열로 처리해 30m(ISO datetime)과
  구분됩니다. 저장·조회는 interval 컬럼 필터로 기존 5m·1d 행과 분리됩니다.
- mock은 30m(5거래일×13봉)·1wk(주 시작일 260개) 결정적 생성으로 동기화됐고,
  intraday 시드가 interval별로 분리되어 5m 경로와 충돌하지 않습니다.
- 기존 range 5종·워치리스트 스파크라인(5m 고정 경로)·벤치마크
  (`get_daily_closes`는 `interval == "1d"` 필터 유지)는 회귀가 없습니다.

## Suggestions

**S1. `get_daily_bars`의 5Y 의미가 "일봉 5년"에서 "주봉 5년"으로 바뀌어, 수집
파이프라인의 5Y 백필 경로와 의미가 충돌합니다.**

PER 5년 배수 히스토리 라운드(#281)에서 `collect_prices_job(range_value="5Y")`
백필이 mock 기준 일봉 1260개를 저장하는 전제로 만들어졌습니다. 이번 변경 후
같은 호출은 주봉(interval `1wk`) 행을 저장하고, 밸류에이션·벤치마크가 쓰는
`get_daily_closes`는 `interval == "1d"` 필터라 그 데이터를 보지 못합니다.
정기 스케줄(3M 일봉)에는 영향이 없고 데이터가 오염되지도 않지만, 향후 일봉
5년 백필이 필요할 때 조용한 no-op이 되는 함정입니다. 필요 시 ingestion 경로에
interval을 명시하는 파라미터를 도입하거나, 백필용 range 별칭을 분리하는 후속을
권장합니다. 비차단입니다.
