# PR #207 로컬 리뷰 — feat: 뉴스 파이프라인 마감 — trust 컬럼 추가·LLM 게이트웨이 수렴 (BE #205·#206)

## Review Summary

PR #201 로컬 리뷰 S2에서 후속 과제로 지목된 두 작업과 데이터 파이프라인 지침 §5.4의
마지막 미충족 항목을 닫는 PR입니다. 커밋 3건으로 구성됩니다. 첫째(설계·핸드오프 문서),
둘째(BE #205), 셋째(BE #206)이며 같은 브랜치에서 순차 구현됐습니다.

**Part A — `NewsItem` 메타데이터 컬럼(BE #205).** `app/domains/news/model.py`에
`trust_level`(String(20), nullable)·`content_hash`(String(64), nullable)를 추가하고,
`alembic/versions/c3d4e5f60059_add_trust_level_content_hash_to_news_items.py`를 수기
작성했습니다. `NewsItemCreate`·`NewsItemResponse` 스키마에 optional 필드를 반영했고,
`ContextBuilder._recent_news_item_from_model`은 `news_item.trust_level`이 None이 아니면
저장값을 사용하고 그렇지 않으면 `_DEFAULT_NEWS_TRUST_LEVEL` 상수로 fallback하도록 변경됐습니다.
이로써 컬럼 추가 이전 레코드는 기존 상수를 그대로 사용하므로 동작이 보존됩니다(Decision BBB).

**Part B — LLM 게이트웨이 수렴(BE #206).** `app/adapters/llm/privacy.py`에
`NewsSummarySnapshot`(PUBLIC)과 `ThesisConflictSnapshot`(AGGREGATED) 두 스냅샷을 추가하고,
`app/adapters/llm/prompts/news_summary.py`·`thesis_conflict.py`를 메시지 리스트 조립자에서
시스템 프롬프트 반환 함수(`build_*_system_prompt()`)로 재편했습니다. 기존 지시문 텍스트는
그대로 보존됐습니다. `NewsAnalysisService`·`ThesisAnalysisService`는 `LLMClient` 직접
주입에서 `LLMGateway` 주입으로 전환됐고, `WatchlistAnalysisService`와 `analysis.py` 잡도
게이트웨이를 경유하도록 연결됐습니다. `app/domains/` 안에 `LLMClient`를 직접 주입받는
분석 서비스가 남아 있지 않음을 diff 전체에서 확인했습니다(Decision CCC).

사용자 메시지 형식이 산문 조립에서 스냅샷 JSON 직렬화로 바뀐 것은 Decision CCC에서
명시적으로 허용된 변경입니다. `gateway.complete_json`이 `CloudSafePayload.as_payload()`
출력을 사용자 메시지로 스스로 조립하므로 호출자가 메시지 리스트를 직접 구성할 필요가
없어졌습니다. 이에 따라 `test_news_analysis.py`·`test_thesis_conflict.py`의 사용자 메시지
단언이 `json.loads(client.messages[1].content)`로 스냅샷 JSON을 검증하는 방식으로 갱신됐습니다.

`MockLLMClient` 직접 주입에 의존하던 테스트는 `LLMGateway({CLOUD: client, LOCAL: client})`
패턴으로 조립한 게이트웨이 주입으로 일관되게 교체됐습니다.

## Suggestions

**S1. `ThesisConflictSnapshot.news_summary` 필드에 `news_item.summary`(Mapped[str | None])를
그대로 전달하는 부분의 암묵적 의존.**
`news_summary: str` 필드에 nullable 값을 넘기려면 상위 코드에 None 가드가 있어야 합니다.
실제 구현에서는 `analyze_conflict` 진입부의 기존 가드가 이를 처리하고 있으며 mypy도 통과했습니다.
그러나 이 관계가 `ThesisConflictSnapshot` 정의에서 보이지 않아 이후 코드 수정 시 가드가
누락될 수 있습니다. 이번 PR 범위에서 변경할 사항은 아니지만, 출처 다양화 시점에 스냅샷
생성 로직을 손볼 때 명시적 처리를 추가하면 좋습니다.

**S2. `_DEFAULT_NEWS_TRUST_LEVEL` 상수의 교체 시점 명확화.**
현재는 fallback 경로에서 하드코딩 상수를 그대로 사용합니다. 출처 다양화 시점에 per-source
신뢰도 정책이 도입되면 이 상수도 함께 교체가 필요합니다. 이는 Decision AAA에서 예고된
후속이며 현재 범위에서는 적절한 처리입니다. 정책 설계 시점에 `_DEFAULT_NEWS_TRUST_LEVEL`이
교체 대상임을 해당 이슈에 기록해 두면 누락을 방지할 수 있습니다.

**S3. 게이트웨이 수렴 경로에 대한 실 워커 스모크 미포함.**
PR #204에서는 `LLM_PROVIDER=mock` 실 워커 스모크 결과를 동봉했지만, 이번 PR에는 포함되지
않았습니다. 게이트웨이·라우터가 변경되지 않았고 `test_analysis_flow.py`의 통합 테스트가
게이트웨이 주입 방식으로 갱신되어 491개 통과로 확인됐으므로 위험도는 낮습니다. 다음 배포
전에 `LLM_PROVIDER=mock` 엔드투엔드 스모크를 한 번 수행해 워커 잡 경로가 실제 프로세스
내에서도 정상 동작하는지 확인하는 것을 권고합니다.
