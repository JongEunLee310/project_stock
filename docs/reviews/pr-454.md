## Review Summary

리서치 Q&A 결과를 Obsidian vault에 Markdown 노트로 저장하는 PR입니다. 커밋은 핸드오프 두 건, Codex
구현 한 건, orchestrator가 실제 노트를 보고 요청한 형식 보정 한 건으로 구성됩니다.

**Part A — 파일 쓰기(#443, 설계 438 §4.3, ADR-018).** `ObsidianWriter.write_research_note`는 vault를
`resolve(strict=True)`로 확인합니다. vault가 없으면 만들지 않고 오류를 냅니다. 종목 코드와
`export_dir`이 안전한 경로 조각인지 검사하고, 디렉터리와 최종 파일 경로가 vault 아래인지 확인합니다.
파일은 `open("x")`로 배타적 생성하고, 이름이 겹치면 `-2`부터 최대 100까지 접미사를 붙입니다. 기존
파일은 열지 않습니다. 날짜는 `generated_at`을 `Asia/Seoul`로 바꿔 씁니다. 반환값은 vault 기준 상대
경로입니다.

**Part B — 노트 형식과 API(#443, 형식 보정 `task-443b`).** `render_research_note`는 frontmatter를 JSON
스칼라(`ensure_ascii=False`)로 직렬화해 YAML double-quoted 문자열로 씁니다. 인용은 Obsidian 각주
`[^n]`, 근거는 각주 정의로 바꿨고 링크 텍스트의 `[`·`]`를 이스케이프합니다. `ResearchQAService`는
`save_to_obsidian`이 참일 때만 writer를 호출하며, writer가 없거나 `OSError`·`ValueError`가 나면 경고
로그만 남기고 `obsidian_note_path=null`로 응답합니다. compose `backend`에 vault 볼륨이 붙고, 기본
위치 `./.obsidian-vault`는 gitignore됩니다.

이번 리뷰는 사용자 파일 보호(덮어쓰기와 경로 탈출), 실패 격리, 실제 Obsidian 표시 형식을 축으로
봤습니다.

## Suggestions

**S1. 인용되지 않은 근거 각주는 읽기 화면에 보이지 않습니다 — 경미, 허용.** Markdown 각주 정의는
본문에서 참조될 때만 렌더링됩니다. 그래서 답변이 인용하지 않은 근거(예: 8개 중 5개만 인용)는 노트
원문에는 남지만 Obsidian 읽기 화면에는 나타나지 않습니다. 같은 이유로 각주 정의가 노트 맨 아래로
모여, 읽기 화면에서 `## 근거` 제목 아래가 비어 보일 수 있습니다. 기록 보존이라는 목적은 원문으로
충족되므로 1차는 허용합니다. 사용자가 Obsidian에서 써 본 뒤 불편하면 "인용된 근거는 각주, 나머지는
일반 목록"으로 나누면 됩니다.

**S2. frontmatter `generated_at`은 UTC이고 파일명 날짜는 서울 기준입니다 — 경미, 허용.** 한국 시간
자정 이후 9시간 동안은 frontmatter 날짜와 파일명 날짜가 하루 다르게 보입니다. 값 자체는 모두
정확합니다(ISO 8601 오프셋 포함). 혼동이 생기면 frontmatter에 서울 시각을 함께 넣으면 됩니다.

**S3. `.gitignore`에 빈 줄이 하나 더 들어갔습니다 — 사소, 허용.** 동작에는 영향이 없습니다.
