# PR #366 로컬 리뷰 — 판단 분석(analytics) API (#364)

## Review Summary

판단 기록 재설계 3차의 시작입니다. 반복 판단 패턴과 품질을 순수 DB 집계로 반환하는 `GET /api/v1/decision-logs/analytics`를 추가합니다. 신규 마이그레이션은 없습니다.

`DecisionLogRepository.aggregate_analytics(user_id, now)`가 지표를 집계합니다: 유형 분포, 확신 수준 분포, 확신별 복기 결과(`decision_logs`⋈`decision_reviews`), 위험 태그 빈도(`decision_risks` group, 내림차순), 재검토 준수율(복기/미복기·도래 판단), 반대 근거 작성률(`CONTRADICTING` evidence 보유 판단 비율). `DecisionAnalyticsService.get_analytics`가 이를 `DecisionAnalyticsResponse`로 매핑하고, 라우트는 `/{decision_log_id}` 보다 먼저 등록됩니다. 두 번째 커밋에서 `process_quality` 평균 산출을 DB 방언별 JSON 집계에서 Python 집계로 바꿔, Postgres 전용 SQL 경로가 SQLite CI로 검증되지 않던 위험을 제거했습니다.

이번 리뷰는 집계 정확성, 0건 안전, 방언 이식성을 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. process_quality 평균의 방언 이식성 — Python 집계로 해소.** 최초 구현은 `func.json_each`/`json_typeof` 기반 방언 분기(postgresql vs sqlite)였고, Postgres 경로가 SQLite 테스트로 검증되지 않아 운영에서 실패할 잠재 위험이 있었습니다. 후속 커밋에서 `process_quality`(자유 JSON)를 파이썬에서 평균 내도록 단순화했습니다 — 사용자당 복기 수가 적어 부담이 없고 방언 무관하게 테스트됩니다. 리뷰 중 조치 완료.

## Questions

**Q1. 0건·결측에서 안전한가.** total_count=0이면 비율 0·빈 목록으로 반환하고, `process_quality`의 결측·비수치 항목(bool 포함)은 평균에서 제외함을 확인했습니다. 0 나눗셈이 없고 테스트가 0건·결측을 덮어 해소됐습니다.

## Final Recommendation

머지 가능합니다. analytics가 유형·확신 분포·확신별 성과·위험 태그 빈도·재검토 준수율·반대 근거 작성률·품질 평균을 사용자 소유 레코드만 대상으로 집계하고, 0건·결측에서 안전하게 반환함을 확인했습니다. process_quality 평균의 방언 위험은 Python 집계로 제거했습니다. 스코프는 집계에 한정돼 유사 판단 검색(#365)·insight AI 문장화·거래 연동은 들어오지 않았습니다. Protected Files는 없습니다. 추가된 테스트는 분포·share 합·반대 근거 비율·확신별 결과·위험 빈도·준수율·품질 평균·0건·타 사용자 격리를 덮습니다. Blocking은 없고 Suggestion S1은 리뷰 중 조치 완료, Question Q1은 확인해 해소했습니다.

최종 머지 권한은 개발자에게 있습니다.
