# PR #229 로컬 리뷰 — feat: 환율 API와 시세 통화 정보 (#228)

리뷰어: value-for-fable (Sonnet — VFF 위임)

## Review Summary

FE의 원화 환산 표시 요구(이슈 #228)를 충족하기 위해 `GET /market/fx` 엔드포인트와
`ExchangeRateProvider` capability를 신설하고, 관심종목 확장 조회 응답에 `currency`
필드를 추가하는 PR입니다.

변경 파일은 14개, 순증 코드량은 +429줄입니다. 구현 구조는 다음과 같습니다.

**신규 capability 추가**: `app/adapters/market/base.py`에 `ExchangeRateResult` frozen
dataclass와 `ExchangeRateProvider` ABC를 추가합니다. 기존 `IndexQuoteProvider` /
`PriceSeriesProvider` / `SymbolLookupProvider`의 capability 분리 패턴을 그대로
따릅니다. 구현체로 `MockExchangeRateProvider`가 추가되고, `get_exchange_rate_provider()`
factory 함수가 `settings.MARKET_PROVIDER` 분기를 처리합니다.

**`fx_service` 신설**: `app/domains/market/fx_service.py`가 신설됩니다.
`ExchangeRateService.get_rates`는 provider를 호출해 `ExchangeRateResponse` 목록으로
변환하며, provider 예외를 502 `MARKET_DATA_PROVIDER_ERROR`로 감싸는 구조가 기존
`index_service.py`와 동일합니다. `parse_fx_pairs`는 쉼표 구분 문자열을 받아 공백을
제거하고 대문자로 정규화하며, 유효한 토큰이 없으면 기본값 `USD/KRW`를 반환합니다.

**`GET /market/fx` 신설**: `app/api/v1/endpoints/market.py`에 `/fx?pairs=` 라우트가
추가됩니다. 응답 envelope·필드 표기(`reference_at`, `UtcDatetime`)는 기존
`/indices` 라우트와 동일한 규약을 따릅니다.

**`AssetBriefResponse.currency` 추가**: `app/domains/watchlists/schema.py`에
`currency: str | None = None` 필드가 추가되고, `list_items_expanded`에서 quote가
있으면 `quote.currency`를, 없으면 `None`을 전달합니다. 기존 필드와 기본값은 변경하지
않으므로 FE 하위 호환이 유지됩니다.

CI는 오케스트레이터 재실행 기준 ruff·mypy·pytest 3종 모두 통과하였습니다.

## Suggestions

**S1. `parse_fx_pairs`의 빈 문자열(`""`) 케이스에 대한 명시적 테스트가 없습니다.**

`parse_fx_pairs(None)` 과 `parse_fx_pairs(" , ")` 는 `tests/test_market_indices.py`
`test_parse_fx_pairs_defaults_when_omitted_or_empty`에서 검증됩니다. 그러나
클라이언트가 `?pairs=`(빈 문자열)를 전송하면 FastAPI는 `""` 을 그대로 전달하며,
`parse_fx_pairs("")`는 `"".split(",")` → `[""]` → `"".strip()` → `""` → falsy 필터
통과 후 기본값 `[DEFAULT_FX_PAIR]`를 반환합니다. 코드는 올바르게 처리하지만
`parse_fx_pairs("")`를 `test_parse_fx_pairs_defaults_when_omitted_or_empty`에
한 케이스로 추가하면 이 경로의 의도를 명시적으로 문서화할 수 있습니다. 핵심 동작과
무관하므로 후속 정리로 처리해도 무방합니다.

**S2. `MockExchangeRateProvider.get_rates`에서 `pair.upper()` 정규화를 provider
계층이 직접 수행합니다.**

`app/adapters/market/mock.py`의 `get_rates`는 `pair.upper()`를 호출해
`_SAMPLE_EXCHANGE_RATES`에서 조회하며, 서비스 계층의 `parse_fx_pairs`도 이미
`.upper()`를 적용합니다. 현재 테스트 코드는 모두 대문자를 넘기므로 실용적 문제는
없습니다. 다만 provider ABC 계약에 입력 형식(대문자 정규화 완료 여부)이 명시되어
있지 않으면, provider를 직접 호출하는 코드가 소문자를 넘겨도 동작한다는 암묵적
기대를 갖게 됩니다. provider 계층의 `pair.upper()` 처리는 방어적 코딩으로 수용
가능하지만, 향후 real provider 구현 시 같은 규칙을 일관되게 적용할지 결정해 두는
것이 좋습니다. 현재 범위에서 머지를 막지 않습니다.

## Final Recommendation

**머지해도 좋다고 판단합니다.** Blocking 항목이 없습니다.

핵심 동작의 정확성을 확인했습니다. `parse_fx_pairs`는 공백 제거·대문자 정규화·빈
입력 기본값을 모두 처리하며, `MockExchangeRateProvider`는 `_AS_OF` 고정 상수
(`datetime(2026, 6, 19, 0, 0, tzinfo=timezone.utc)`)를 사용해 결정성이 코드
수준에서 보장됩니다. 미지원 페어는 `_SAMPLE_EXCHANGE_RATES.get(pair.upper())`가
`None`을 반환할 때 결과 목록에서 조용히 제외되어 설계 명세와 일치합니다.
`AssetBriefResponse.currency: str | None = None` 추가는 기존 필드와 기본값을 변경하지
않으므로 FE 하위 호환이 유지됩니다.

핸드오프 Test Requirements 4개 범주(`MockExchangeRateProvider` 단위, `GET /market/fx`
엔드포인트, 관심종목 확장 조회 currency 보강, factory 분기)가 모두 구현되었고,
기존 테스트는 약화 없이 유지됩니다. S1은 후속 테스트 문서화 정리, S2는 real provider
구현 진입 전 계약 명시 사항으로, 현재 범위에서 머지를 막지 않습니다.

최종 머지 권한은 개발자에게 있습니다.
