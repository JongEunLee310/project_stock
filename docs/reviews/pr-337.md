## Review Summary

BE 에픽의 마지막 조각인 알림 엔진입니다. `AlertEvaluator`(스냅샷 기반 순수 평가)·
`AlertDedupService`(dedup_key + cooldown + state-transition)·`AlertEngineService.run_cycle()`·
`MetricSnapshotProvider`를 신설하고, `evaluate_alert_rules_job` 워커 잡과 스케줄러 등록
(`ALERT_ENGINE_ENABLED` 게이트, 기본 false, 5분 주기)을 추가합니다. 기존 잡 패턴
(`SessionLocal` + `JobRunService` + commit)과 스케줄러 registry 패턴을 그대로 따릅니다.

중복 방지(`dedup.py`)가 설계 §6과 정확히 일치합니다: `should_emit`이 matched → cooldown →
`ONCE_PER_TRANSITION`(전이 시에만) → `ONCE_PER_DAY`(하루 1회) → `dedup_key` 존재 순으로
검사하고, `dedup_key`는 `rule_id:target_id:sha256(fingerprint)`(ONCE_PER_DAY는 날짜 포함)로
구성됩니다. cooldown·day 경계는 UTC 기준(프로젝트 관례)이며 tz-naive 값도 안전하게 UTC로
정규화합니다. `AlertEvent`의 `UniqueConstraint(user_id, dedup_key)`가 2차 방어선입니다.
`AlertEvaluator`는 조건에 미지원/미가용 지표가 있으면 `matched=False`로 처리해 오발동·예외
없이 안전하게 건너뛰고, 엔진은 어떤 경로에서도 `Signal`을 생성하지 않습니다(ADR-013 §15).

## Non-blocking

**N1(가장 중요). 지표 3종이 미지원으로 남아 해당 활성 템플릿이 아직 발동하지 않습니다.**
`MetricSnapshotProvider.UNSUPPORTED_METRICS`에 `NEWS_RISK`·`THEME_HEAT`·`AI_JUDGMENT_CHANGED`·
`TOPIC_IMPACT_SCORE`가 포함됩니다. 앞 3종은 활성 템플릿(HOLDING_NEWS_RISK·
WATCHLIST_AI_JUDGMENT·NEWS_RISK_HIGH)을 뒷받침하므로, 연동 전까지 이 규칙들은 평가 시
`matched=False`로 발동하지 않습니다. 이는 핸드오프의 "소싱 못 하면 stub 금지·미지원 보고"
지침을 따른 정직한 결과이며, 후속 이슈 **#336**으로 분리했습니다(watchlist 최신 스냅샷 소싱).
연동 완료 지표(PRICE_CHANGE_1D·SIGNAL_CHANGED·POSITION_WEIGHT·EARNINGS_DATE)는 정상
동작합니다.

**N2. 스케줄러 잡이 기본 비활성(`ALERT_ENGINE_ENABLED=false`)입니다.** 기존
`ANALYSIS_SCHEDULE_ENABLED` 관례를 따른 안전한 기본값이며, 실동작 확인 시 환경에서 활성화하면
됩니다. 5분 주기는 MVP 기준 적절합니다.
