# PR #363 로컬 리뷰 — 판단 재검토 트리거 감시 엔진 (#360)

## Review Summary

판단 기록 2차의 이벤트 기반 재검토 트리거 감시 엔진입니다. 트리거 조건이 충족되면 판단을 `REVIEW_DUE`로 전이합니다. 사용자 확정에 따라 Alert 도메인과 연동하지 않고 상태 전이만 하며, ADR-013 경계를 넘지 않아 신규 ADR이 없습니다. 신규 마이그레이션도 없습니다.

`app/domains/decision_logs/review_trigger_service.py`의 `DecisionReviewTriggerService.run_cycle()`가 핵심입니다. `repository.list_pending_event_triggers()`로 대상 판단이 `ACTIVE`인 PENDING `PRICE`·`SIGNAL_CHANGE` 트리거를 로드하고, 유형별로 조건을 평가합니다. `PRICE`는 `PriceBarRepository.get_latest_by_symbol`로 최신가를 받아 `{op: gte|lte, value}`와 Decimal로 비교하고, `SIGNAL_CHANGE`는 심볼로 자산을 찾아 `SignalService.list_current_signals`의 현재 시그널 유형이 `{to}`와 같은지 확인합니다. 충족 시 `repository.mark_triggered`로 트리거를 `TRIGGERED`(+`triggered_at`)로, 판단을 `REVIEW_DUE`로 전이합니다. `ValidationError`·`ValueError`와 데이터 부재는 해당 트리거를 건너뜁니다. 워커 잡 `evaluate_decision_review_triggers_job`(`app/worker/jobs/`)이 이 주기를 `JobRunService`로 기록하며, `app/scheduler/registry.py`에 5분 주기(`*/5 * * * *`)로 기존 `alert_evaluation`과 동일 패턴으로 등록됐습니다. `review-queue`와 overview `review_due_count`는 `status == REVIEW_DUE` 판단을 합집합으로 포함하도록 확장됐습니다.

이번 리뷰는 조건 평가의 정확성, 상태 전이 가드, 안전 skip, 기존 review-queue·overview 회귀를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. `METRIC`·`EVENT` 트리거는 스키마만·평가 미구현 — 설계 확정 범위, 후속.** 두 유형은 조건 스키마만 정의되고 `_is_condition_met`에서 매칭되지 않아 PENDING으로 유지됩니다. 설계 §1·§5가 평가를 후속으로 명시했고 데이터 매핑(밸류에이션 지표·이벤트) 작업이 필요해, 이번 스코프에서 제외한 것이 맞습니다. 후속 이슈로 두면 됩니다.

**S2. `SIGNAL_CHANGE`가 "변경"이 아니라 "현재 상태 일치"로 평가 — 설계와 일치, 인지.** 조건은 현재 시그널 유형이 `to`와 같은지만 봅니다(직전 대비 변화 추적 아님). 설계 §1이 "현재 시그널 유형이 `to`와 같으면 충족"으로 정의했으므로 계약과 일치합니다. 변화 이력 기반 평가가 필요하면 시그널 스냅샷(`asset_signal_snapshots`)을 쓰는 후속으로 확장할 수 있습니다.

## Questions

**Q1. 이벤트 전이가 review-queue·overview에 이중 계상되지 않는가.** 트리거로 `REVIEW_DUE`가 된 판단은 트리거가 `TRIGGERED`로 바뀌어 기존 "PENDING DATE" 조회에서 빠지고, 대신 `status == REVIEW_DUE` 합집합으로 포함됩니다. 판단 단위 중복 제거가 유지되는지 테스트로 확인했고, 기존 DATE review-queue 동작 회귀가 없음을 확인해 해소됐습니다.

## Documentation Impact

설계문서 `docs/designs/360-review-trigger-engine.md`가 이번 PR에 포함돼 정본입니다. ADR은 불필요합니다 — 트리거 충족이 판단 도메인 내부 상태 전이만 일으키고 Alert 연동이 없어 ADR-013 경계를 넘지 않으며, ADR-016 재검토 조건 개념의 계획된 구현입니다. Failure Record도 불필요합니다.

## Final Recommendation

머지 가능합니다. 엔진이 PENDING `PRICE`·`SIGNAL_CHANGE` 트리거를 현재가·현재 시그널과 비교해 충족 시 트리거 `TRIGGERED`·판단 `REVIEW_DUE`로 전이하고, 비-`ACTIVE` 판단은 전이하지 않으며, 데이터 부재·조건 파싱 실패를 개별 skip해 1건 실패가 주기를 막지 않음을 확인했습니다. 워커·스케줄러 등록은 기존 `alert_evaluation` 패턴을 따르고, review-queue·overview는 `REVIEW_DUE` 합집합으로 확장되며 기존 DATE 로직을 유지합니다. 스코프는 `PRICE`·`SIGNAL_CHANGE`에 한정돼 `METRIC`·`EVENT` 평가와 Alert 연동은 들어오지 않았습니다. Protected Files는 없습니다. 추가된 테스트는 조건 충족/미충족 전이·비-ACTIVE 미전이·데이터 부재 skip·review-queue/overview 포함·스케줄 등록을 덮습니다. Blocking은 없고 Suggestions S1·S2는 각각 후속·설계 일치로 정리됐으며 Question Q1은 리뷰 중 확인해 해소했습니다.
