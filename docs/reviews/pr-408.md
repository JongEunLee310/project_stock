# PR #408 로컬 리뷰 — 뉴스 토픽 군집 배관·골격 군집기 (#399)

## Review Summary

2단계(#398)로 생성된 `extracted_events`를 토픽으로 묶어 `topic_clusters`·`topic_keywords`·
`keyword_relations`로 파생하는 군집 경로를 만드는 PR입니다. 트래킹 #391의 3단계이며, 설계는
`docs/designs/399-clustering-topics-keywords.md`에 확정돼 있습니다. 단일 커밋으로 신규 모듈
하나(`clustering.py`)와 테스트 네 건을 더합니다. 모델·스키마·마이그레이션 변경은 없습니다.

이번 단계의 방침은 **배관·계약 우선, 스키마 유지**입니다. `topic_clusters`에는 event↔topic
membership 저장 자리가 없고 골격 단계의 그룹핑 신호가 `event_type` 정도뿐이므로, 스키마를
바꾸지 않고 매 실행 `extracted_events` 전체에서 토픽을 결정론적으로 재파생합니다. 실
클러스터링·키워드 추출·membership 저장·추이 정교화는 후속 #407로 분리했습니다.

이번 리뷰는 집계가 실측인지(placeholder와 섞이지 않는지), `slug` upsert 멱등이 집계 누적 없이
성립하는지, `EventType` → `TopicCategory` 매핑이 완전한지(KeyError 위험), 그리고 값을 지어내지
않는 원칙(빈 관계망)이 지켜지는지를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 매 실행 `extracted_events` 전체를 재조회·재집계한다 — 스냅샷 재파생의 본질이나 대량에서는
비용이 된다.** `cluster_topics`는 전체 이벤트를 읽어 재집계하고 한 번에 커밋합니다. 이는 집계
누적을 피하고 멱등을 얻기 위한 올바른 방식이지만, 이벤트가 대량으로 쌓이고 주기 실행이 붙는
시점(#407)에는 증분 군집으로 좁힐 후보입니다. 현재 규모에서는 문제가 아닙니다.

**S2. `EventType` → `TopicCategory` 매핑에 판단이 개입한 항목이 있다 — 골격 매핑으로 수용.**
예를 들어 `MANAGEMENT_CHANGE` → `MARKET_EVENT`는 자명하지 않습니다. 다만 `category`는 골격
단계의 참고 분류이고 매핑은 결정론적 규칙으로 명시돼 있으며, 의미 있는 분류는 실 클러스터링
(#407)에서 재검토됩니다. 매핑 자체는 `EventType` 8종을 빠짐없이 덮어 KeyError 위험이 없습니다
(아래 Q1).

## Questions

**Q1. 매핑에 없는 `EventType`이 들어오면 군집 전체가 실패하지 않는가.** 확인해 해소했습니다.
`_EVENT_TYPE_CATEGORIES[event_type]`는 딕셔너리 직접 인덱싱이라 누락 키가 있으면 KeyError로
`cluster_topics` 전체가 실패합니다. `EventType` enum 전체(EARNINGS_GUIDANCE·BUYBACK·
REGULATION·SUPPLY_CONTRACT·MANAGEMENT_CHANGE·ACCOUNTING_ISSUE·PRODUCTION_DISRUPTION·OTHER)가
매핑에 모두 있어 현재 위험은 없습니다. `OTHER`까지 포함돼 있어 유형이 늘지 않는 한 안전합니다.

## Final Recommendation

머지 가능합니다. 설계 §2~6의 Port·골격 군집기·slug upsert·실측 집계를 항목별로 확인했습니다.
`mention_count`·`sentiment_score`가 소속 이벤트에서 실측 집계되고, `momentum`·`impact`·
`confidence`는 placeholder로 분리돼 값을 지어내지 않으며, 신호가 없는 관계망은 빈 상태로
둡니다.

범위는 지켜졌습니다. 스키마·모델·마이그레이션을 변경하지 않았고(membership은 #407), 실
클러스터링·키워드 추출을 끌어들이지 않았으며, 해석·추출·수집 로직을 건드리지 않았습니다.
Protected Files는 없습니다.

테스트는 event_type별 그룹핑과 실측 집계의 값 단언, `slug` upsert 멱등(재실행 시 행 수·집계
불변), 새 이벤트 추가 후 재계산(mention_count 1→2·sentiment 재평균·last_activity_at 갱신),
빈 입력을 덮습니다. 필드 존재만 확인하는 단언은 없습니다.

Blocking은 없습니다. S1·S2는 이 PR이 늘린 위험이 아니라 후속(#407)의 후보이고, Q1은 확인해
매핑 완전성으로 KeyError 위험이 없음을 확인했습니다.

최종 머지 권한은 개발자에게 있습니다.
