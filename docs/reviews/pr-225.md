# PR #225 로컬 리뷰 — feat: 종목 추천 API 신설 (#222)

리뷰어: value-for-fable (Sonnet — VFF 위임)

## Review Summary

관심 목록에 아직 포함되지 않은 활성 종목을 후보로 구성하고, 공개 시장 지표를
CloudSafe projection에 담아 LLM에게 추천을 요청하는 `GET
/api/v1/watchlists/{watchlist_id}/recommendations` 엔드포인트를 신설하는 PR입니다.

구현은 기존 LLM 게이트웨이(`LLMGateway.complete_json`), `WatchlistObservationSnapshot`
패턴, `PrivacyGate` 경유 모두를 그대로 재사용하고 신규 경로만 추가했습니다. 핵심
설계 결정은 세 가지입니다. 첫째, LLM에 전달하는 payload가 공개 종목 정보와 집계된
시그널 상태만 포함하므로 ADR-009 `AGGREGATED` 등급으로 정당화됩니다. 둘째, LLM이
반환한 심볼을 후보 목록과 교차 검증해 외부 심볼 주입을 방어합니다. 셋째, 후보가
없으면 LLM을 호출하지 않고 빈 목록을 즉시 반환합니다. 결과를 영속화하지 않으므로
DB 스키마 변경은 없습니다.

변경 파일은 14개이고 테스트는 362줄 신규 추가됩니다. 기존 파일에 대한 수정은 각
어댑터(`types.py`·`router.py`·`privacy.py`·`schema.py`·`mock.py`)와
`watchlists/schema.py`·`watchlists.py` 엔드포인트에 기존 패턴 방식으로 최소
항목을 추가하는 방식이며, 기존 경로를 변경하지 않습니다.

## Suggestions

**S1. `test_watchlist_recommendations_service_filters_symbols_outside_candidates`에서
market provider를 명시적으로 패치하지 않습니다.** 이 테스트는 `_build_candidates`를
거치므로 내부에서 `get_market_provider().get_quote(["AAPL"])`가 호출됩니다. 같은
파일의 `test_watchlist_recommendations_service_excludes_current_items_and_maps_result`는
`monkeypatch`로 `get_market_provider`를 명시적으로 교체하는데, 이 테스트는 `.env`의
`MARKET_PROVIDER=mock` 기본값에 암묵적으로 의존합니다. 기능상 문제는 없고 현재
환경에서 통과하지만, 테스트 의도(심볼 필터링 검증)와 무관한 환경 의존성이 생겨
같은 파일 내 패턴이 불일치합니다. 다른 서비스 테스트와 일관성을 맞추거나 의존성을
주석으로 명시하면 유지보수성이 좋아집니다.

**S2. `_project_recommendations`에서 심볼 대소문자를 정규화하지 않습니다.** 후보
목록(`assets_by_symbol`)은 `asset.symbol` 원본 그대로 키를 구성하고, LLM 반환
`item.symbol`도 정규화 없이 조회합니다. snapshot payload가 후보 심볼을 그대로
LLM에 전달하므로 LLM이 동일 대소문자로 반환할 것을 묵시적으로 가정합니다. 실제
장애 가능성은 낮지만, `assets_by_symbol = {asset.symbol.upper(): asset ...}` 와
`assets_by_symbol.get(item.symbol.upper())` 로 방어 처리하면 LLM 출력 변이에
안전해집니다.

**S3. 설계 문서 §13 가정 표가 구현 완료 상태를 반영하지 않습니다.** `Status:
Implemented`로 갱신됐으나 가정 A~E 항목에 "확정 값"이나 "확정됨" 표기가 없습니다.
특히 가정 D(`"AAPL"` 심볼)는 PR 본문에서도 "구현 시 테스트 픽스처와 일치시킨다"고
명시한 사항으로, 구현에서 확정된 내용이 설계 문서에 다시 반영되면 이후 참조 시
혼동이 줄어듭니다.

## Final Recommendation

**머지해도 좋다고 판단합니다.** Blocking 항목이 없습니다.

설계 §8의 10단계 처리 순서가 `recommendations_service.py`에 순서 그대로 구현됐습니다.
CloudSafe 경계는 `StockRecommendationSnapshot.sensitivity = AGGREGATED`로 선언하고
`PrivacyGate.guard`가 `gateway.complete_json` 내부(line 102)에서 cloud 호출 전에
적용되어 ADR-009 계약을 지킵니다. 보유 수량·평가액은 payload에 포함되지 않습니다.
방어 로직 세 가지(심볼 교차 검증·5개 cap·빈 후보 early return)가 모두 코드와
테스트에 존재하며 `FailingGateway`를 활용해 LLM 미호출도 검증합니다.
`ErrorCode.WATCHLIST_NOT_FOUND`·`WATCHLIST_FORBIDDEN`은 `watchlists/service.py`와
동일하고 라우트 테스트에서 에러 코드 문자열까지 검증합니다. 기존 테스트 약화나
보호 파일 변경은 없습니다.

Suggestions는 모두 후속 개선 사항으로, 현재 범위에서 merge를 막지 않습니다. S1은
테스트 일관성 권고이고, S2는 방어 강화 옵션이며, S3는 설계 문서 정리입니다. 최종
머지 권한은 개발자에게 있습니다.
