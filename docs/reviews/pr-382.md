# PR #382 로컬 리뷰 — 뉴스 인텔리전스 종목 민감도·키워드 관계망 계약 (#369)

## Review Summary

뉴스·공시 인텔리전스(에픽 #307) 2차의 토픽 상세 두 패널로, `GET /topics/{id}/symbols`(종목 민감도)와 `GET /topics/{id}/graph`(키워드 관계망)를 추가합니다. 브랜치는 #368(#381)·#380·#306(#379) 위에 스택돼 있으나 PR base는 dev이며 커밋은 1건입니다.

**Part A — 종목 민감도(#369, 설계 §3.3).** `service.get_topic_symbols`가 2차 골격 `topic_symbol_sensitivity`를 조회해 종목별 `exposure_score`·`impact_direction`·`relationship`(DIRECT/SUPPLY_CHAIN/COMPETITOR/CUSTOMER)·`valuation_burden`을 반환합니다. `exposure_score`와 `impact_direction`을 분리 필드로 둬 노출도 높음+부정 조합을 표현할 수 있습니다. `portfolio_weight`·`current_signal`은 nullable로 두고 실조인은 하지 않았습니다(아래 S1). `current_signal`은 signals 도메인의 `SignalType`을 재사용합니다.

**Part B — 키워드 관계망(#369, 설계 §3.4).** `get_topic_graph`가 1차 `keyword_relations`·`topic_keywords`로 토픽 내부 관계망을 조립합니다. node는 `KEYWORD` 타입에 `mention_count`·`sentiment_score`·`related_event_ids`·`related_symbols`(클릭 필터링용 참조)를, edge는 `strength`·`cooccurrence_count`를 담습니다. 연관 강도(edge)와 감성(node)을 분리합니다. 개요 토픽 맵(#303)과 달리 단일 토픽 내부에 한정된 상세 그래프입니다. 두 라우트 모두 미존재 토픽에 `NEWS_INSIGHT_TOPIC_NOT_FOUND` 404를 반환합니다.

이번 리뷰는 설계 §3.3·§3.4 계약 일치, 노출도/감성 분리, 크로스 도메인 필드의 처리를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. `portfolio_weight`·`current_signal` nullable 유지 — 설계가 허용한 범위, 실조인은 후속.** 설계 §2.2·§3.3은 두 필드를 조회 시 portfolios·signals에서 조인하도록 열어뒀으나, endpoint에 `portfolio_id`가 없고 평가 비중 저장이 없어 이번 범위에서는 nullable로 뒀습니다(복수 포트폴리오 임의 합산 회피). 핸드오프가 명시적으로 이 선택을 허용했고 PR 본문에 기록됐습니다. 실조인 도입 시 포트폴리오 선택·평가 기준 확정이 필요하며, FE(project_stock_frontend#265)는 null을 "미보유·시그널 없음"으로 표시하면 됩니다.

**S2. graph node가 `KEYWORD` 타입만 — 토픽 내부 관계망 성격에 부합.** 개요 토픽 맵(#303)은 TOPIC/KEYWORD 노드를 갖지만, 이 그래프는 단일 토픽 내부 키워드 관계이므로 `Literal["KEYWORD"]`만 둔 것이 자연스럽습니다. 설계 §3.4와 배치되지 않습니다.

## Questions
