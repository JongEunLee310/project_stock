# PR #357 로컬 리뷰 — 판단 작성 AI 보조 endpoint (#356)

## Review Summary

판단 작성 폼의 AI 보조를 위한 비영속 LLM 엔드포인트를 추가합니다. 디자인 이미지의 순수 수기 작성 폼에 AI agent 보조를 더하는 스코프이며, 사용자 초안을 받아 제안만 반환하고 저장하지 않습니다.

기존 LLM 인프라를 재사용합니다. `app/adapters/llm/gateway.py`의 `LLMGateway.complete_json(task_type, payload, schema, system_prompt)`를 호출하고, 신규 `LLMTaskType.DECISION_ASSIST`를 `app/adapters/llm/router.py`의 `LLM_TASK_ROUTES`에 `launch=cloud`/`future_primary=local`로 등록했습니다. 클라우드로 나가는 입력은 `DecisionAssistSnapshot(CloudSafePayload)`(`app/adapters/llm/privacy.py`, `sensitivity=AGGREGATED`)로 감싸 `target_type`·`symbol`·`decision_type`·`thesis`·`rationale`·`memo`만 화이트리스트로 싣습니다. 응답은 `DecisionAssistResult`(structured_thesis·structured_rationale·counter_arguments·risk_candidates·bias_candidates·vague_flags)로 파싱합니다. `POST /api/v1/decision-logs/assist`는 `DecisionAssistService.assist`로 위임하고, 서비스는 LLM 예외를 잡아 빈 제안을 반환해 작성 흐름을 막지 않습니다. Repository는 없습니다(비영속).

이번 리뷰는 설계문서(`docs/designs/356-decision-assist.md`) 준수, AI 보조 원칙(판단 대체 금지·편향은 점검 후보), CloudSafe 경계(ADR-009), 비영속·안전 실패를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 자유 텍스트 초안의 CloudSafe 민감도 `AGGREGATED` 표기 — 현재 경계에서 허용, 인지 필요.** `DecisionAssistSnapshot`은 사용자 자유 서술(thesis·rationale·memo)을 담는데 `sensitivity=AGGREGATED`로 표기됐습니다. 보조 기능의 특성상 초안 텍스트는 클라우드로 나가야 하고, `CloudSafePayload` 상속으로 화이트리스트 필드만 직렬화되며 내부 ID·타 사용자·타 도메인 스냅샷은 실리지 않음을 확인했습니다(privacy 게이트 통과). 자유 텍스트를 더 높은 민감도로 다룰지는 운영에서 정책적으로 판단할 여지가 있으나, 현재 CloudSafe 경계(ADR-009) 안에서 허용 가능합니다.

**S2. 보조 입출력의 감사 이력 부재 — 설계상 비영속, 후속 판단 사항.** 엔드포인트는 DB 기록을 남기지 않아 어떤 초안이 LLM에 갔고 어떤 제안이 왔는지 감사 이력이 없습니다. 설계 §7이 비영속을 명시했고 제안은 사용자가 [적용]해야 정식 저장되므로 1차에서는 정상입니다. 향후 품질·비용 추적이 필요하면 별도 로깅/집계를 후속으로 두면 됩니다.

## Questions

**Q1. `/assist` 경로가 `/{decision_log_id}`와 충돌하지 않는가.** `POST /assist`는 리터럴 경로이고 파라미터 라우트(`GET`/`PATCH /{decision_log_id}`, `POST /{decision_log_id}/activate`)와 메서드·경로가 겹치지 않습니다. 엔드포인트 등록에서 `/assist`가 별도 라우트로 매칭됨을 확인해 해소됐습니다.

## Documentation Impact

설계문서 `docs/designs/356-decision-assist.md`가 이미 커밋돼 정본입니다. ADR은 불필요합니다 — 설계 §6이 근거를 답니다. 본 엔드포인트는 ADR-016 §7(AI는 판단을 대신하지 않고 구조화·검증만, 제안은 확인 후 저장)의 구현이자 ADR-009(CloudSafe 경계)의 적용이며, 새로운 아키텍처 방향 선택이 아닙니다. Failure Record도 불필요합니다.

## Final Recommendation

머지 가능합니다. 구현이 설계 §1~§5와 일치함을 항목별로 확인했습니다. 엔드포인트·요청/응답 스키마·CloudSafe 스냅샷 화이트리스트·router 매핑·프롬프트가 계약대로이고, 프롬프트는 "판단을 대신 확정하지 말 것, 위험·편향은 점검 후보로만, 사용자 텍스트 근거로만, 모호 표현엔 보완 제안"을 명시해 AI 보조 원칙을 코드에 담았습니다. 비영속이라 Repository·DB 변경이 없고, LLM 실패는 빈 제안으로 안전 반환해 작성 흐름을 막지 않습니다. 스코프는 assist에 한정돼 관련 근거 자동 연결·복기·영속화는 들어오지 않았습니다. Protected Files는 없으며, LLM 어댑터는 신규 task_type·payload·prompt·router 매핑 추가에 그쳐 기존 task 동작을 바꾸지 않습니다(회귀 테스트 포함). 추가된 테스트는 제안 매핑·CloudSafe 화이트리스트·인증/검증·LLM 실패 안전 처리·기존 task 회귀를 덮습니다. Blocking은 없고 Suggestions S1·S2는 각각 현재 경계 허용·비영속 설계로 정리됐으며, Question Q1은 리뷰 중 확인해 해소했습니다.
