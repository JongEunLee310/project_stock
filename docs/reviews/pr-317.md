## Review Summary

이 PR은 intraday 가격 봉 간격 표준을 15분에서 5분으로 전환합니다. 리서치 가격 차트(`GET /stocks/{symbol}/prices?range=1D`)와 워치리스트 스파크라인(`GET /watchlists/{id}/sparklines?range=1D`)이 `app/domains/prices/service.py`의 `_RANGE_INTERVALS`·`_RANGE_COUNTS` 매핑을 공유하는 기존 구조를 그대로 활용했고, 변경은 이 두 딕셔너리의 값 수정(`"1D": "15m"` → `"5m"`, `26` → `78`)에서 시작해 provider 두 곳과 테스트·문서로 파급되는 형태입니다.

`app/adapters/market/yfinance.py`는 `ticker.history(period="1d", interval="15m", ...)` 호출과 `PriceBarResult.interval` 리터럴을 `"5m"`으로 바꿨고, `app/adapters/market/mock.py`는 `_INTRADAY_BAR_COUNT`를 78로, 바 간격을 `timedelta(minutes=5 * index)`로 바꿔 실제 provider와 mock provider가 동일한 봉 수·간격을 생성하도록 맞췄습니다. `app/domains/watchlists/sparkline_service.py`는 diff에 나타나지 않는데, 확인해 보니 이 파일이 `from app.domains.prices.service import PriceSeriesService, _RANGE_INTERVALS`로 매핑을 직접 임포트해서 쓰는 구조라 `service.py`의 값만 바꾸면 워치리스트 스파크라인 경로도 자동으로 동기화됩니다. 별도 수정이 빠진 게 아니라 애초에 단일 소스여서 손댈 필요가 없었던 것으로, 핸드오프 문서가 "동기화 확인"을 요구한 항목이 구조적으로 이미 충족되어 있었습니다.

78이라는 봉 수는 미국·한국 정규장 6.5시간(390분) ÷ 5분 = 78로, 기존 26(390÷15)과 같은 산식을 유지한 값입니다. 테스트는 `test_price_ingestion.py`·`test_price_series.py`·`test_watchlist_sparklines.py` 세 파일에서 interval 리터럴과 봉 수 기대값을 78로 갱신했고, `test_price_series_service_uses_intraday_provider_for_1d`는 기존 `<= 26` 부등식을 `== 78`로 바꿔 mock provider가 정확히 78개를 반환하는지 등호로 검증하도록 강화했습니다. 문서는 `docs/designs/price-series-api.md`·`docs/designs/239-watchlist-1d-intraday.md`(버전 이력 R1 한 줄 추가 후 본문 15m→5m 치환)·`docs/api/frontend-api-spec.md`가 모두 갱신되었습니다.
