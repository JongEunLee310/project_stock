# PR #453 로컬 리뷰 — feat: RAG 1차 종목 리서치 Q&A API(검색·생성·인용 검증) (#442)

## Review Summary

종목 리서치 Q&A API `POST /api/v1/assets/{asset_id}/research-qa`를 추가하는 PR입니다. 커밋은
핸드오프 한 건과 Codex 구현 한 건으로 구성됩니다.

**Part A — 검색과 근거 구성(#442, 설계 438 §5.2).** `ResearchQAService.ask`는 asset을 확인하고 질문을
임베딩한 뒤, `ChunkFilter`(현재 모델, 해당 종목, `NEWS`, `lookback_days` 이후)로 후보 20개를
검색합니다. `postprocess_hits`가 하한 0.3 미만 제거, `TITLE_ONLY` 가중치 0.8, 원문당 2청크, 상위
8개를 적용합니다. 원문 메타데이터는 새 `RawNewsEventRepository.list_by_ids`로 한 번에 읽고(ADR-018
R2), 매체명은 `extract_source_name`이 제목의 ` - 매체명` 꼬리에서 가져옵니다. `raw_news_events.source`가
실매체가 아니라 Google News 피드 제목이기 때문입니다.

**Part B — 생성과 검증(#442, 설계 438 §5.3~§5.5, ADR-009).** 근거가 0건이면 LLM을 호출하지 않고
`insufficient_evidence=true`로 응답합니다. 근거가 있으면 `ResearchQASnapshot`(종목, 질문, 번호가 붙은
근거만, 내부 식별자 없음)을 `LLMGateway.complete_json(RESEARCH_QA, ...)`에 넘깁니다. 프롬프트 v1은
근거 한정, 전 항목 인용, 헤드라인 한계 공개, 매수·매도 권유 금지, 질문·근거를 지시로 취급하지 않음을
지시합니다. 응답은 `validate_citations`로 없는 번호와 중복 번호를 지우고, 인용이 없는 항목을 버립니다.
LLM 예외는 200 안전 응답(근거 유지)으로, 질문 임베딩 실패는 503 `RAG_EMBEDDING_UNAVAILABLE`로
바뀝니다. PR #452 리뷰 S1(임베딩 실패 메시지)도 함께 정리됐습니다.

이번 리뷰는 근거 없는 생성 차단, 인용 무결성, 클라우드 전송 범위, 실제 LLM에서의 동작을 축으로
봤습니다.

## Blocking

None.

## Suggestions

**S1. 유사도 하한 0.3이 무관한 근거를 걸러 내지 못합니다 — 중간, #444 평가에서 조정.** 실제 LLM
검증에서 "NVDA 양자컴퓨터 진출 계획은?"에 대해 무관한 기사들이 0.35 안팎으로 근거 8건을 채웠습니다.
LLM이 "관련 근거 없음"으로 올바르게 답했지만, 무관한 근거가 클라우드로 전송되고 생성 시간(16.7초)을
씁니다. 같은 실험에서 관련 근거는 0.41~0.72였습니다. 하한을 정할 근거 데이터가 #444 평가 세트에서
나오므로, 그때 하한(예: 0.4 전후)과 `TITLE_ONLY` 가중치를 함께 조정하면 됩니다.

**S2. 응답에 16~26초가 걸립니다 — FE 연동 시 반영 필요.** 대부분이 LLM 생성 시간입니다. 동기
엔드포인트로 충분하지만, FE(`project_stock_frontend#308`)에 로딩 상태와 넉넉한 요청 타임아웃이 필요합니다.
FE 이슈에 이 수치를 공유하겠습니다.

**S3. `insufficient_evidence=true`인데 `answer_points`가 있는 응답이 나옵니다 — 경미, 계약 해석 명시
권장.** 실제 LLM은 "근거 부족" 판단을 내리면서도 그 이유를 인용과 함께 항목으로 설명했습니다. 이 동작
자체는 사용자에게 유용합니다. 다만 FE가 `insufficient_evidence`만 보고 답변을 숨기지 않도록, 설계 438
§5.1과 API 문서에 "부족 판정과 설명 항목이 함께 올 수 있다"를 한 줄 적어 두면 좋겠습니다. #443에서
같은 문서를 고칠 때 반영하겠습니다.

## Questions

**Q1. 실제 LLM에서도 근거 한정과 인용 규칙을 지키는가 — 리뷰 중 확인해 해소했습니다.** 로컬 볼륨
복제본(2,703건 임베딩), 실제 Ollama `bge-m3`, pgvector, 실제 LLM(openai-oauth 프록시)으로 네 질문을
호출했습니다.

- NVDA 최근 주요 리스크: 5개 항목, 모두 유효 인용, 한계에 "제목 수준이라 구체적 영향은 확인 불가"
  명시(25.5초)
- NVDA 최근 분기 매출 성장률: `insufficient=true`, 근거에 없는 수치를 만들지 않음(15.8초)
- AAPL–브로드컴 계약: 규모·기간·투자를 근거 4건 이상 인용해 답함, 근거 점수 0.66~0.72(26.3초)
- NVDA 양자컴퓨터 진출: `insufficient=true`, 관련 근거 없음을 정확히 답함(16.7초)

**Q2. 사용자 질문의 클라우드 전송 — 개발자 확인이 필요합니다.** 질문은 사용자가 쓴 자유 텍스트라
`ResearchQASnapshot`에 그대로 실려 클라우드 LLM으로 나갑니다. 선례는 `DecisionAssistSnapshot`이고,
설계 438 §5.3과 FE 이슈(#308)에 "개인 정보를 적지 말라"는 안내를 두기로 했습니다. ADR-009 경계에서
이 처리가 괜찮은지 확인해 주세요.

## Final Recommendation

머지 가능합니다. 근거가 0건일 때 LLM 호출이 0회인지(테스트 세 곳의 `assert_not_called`), 응답 인용이
모두 근거 번호 안에 있는지, 클라우드 payload에 내부 식별자가 없는지, LLM과 임베딩 실패가 각각 안전
응답과 503으로 바뀌는지를 코드와 테스트로 확인했고, 실제 LLM으로도 근거 한정과 수치 비날조를
확인했습니다. 범위는 #442에 한정되고 Obsidian과 평가 세트는 들어오지 않았습니다. protected 파일
변경은 없습니다. 테스트는 검색 후처리, 매체명 추출, 인용 검증, 프롬프트·projection 계약, 기간·종목
필터, 근거 없음, LLM·임베딩 실패, 입력 검증, 인증, 그리고 인덱서부터 API까지 관통하는 실제 경로를
덮습니다. Blocking은 없습니다. S1은 #444에서, S2는 FE 연동에서, S3는 #443에서 처리합니다. Q1은
해소했고 Q2는 개발자 확인을 요청합니다.

최종 머지 권한은 개발자에게 있습니다.
