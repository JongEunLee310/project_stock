# PR #272 로컬 리뷰 — feat: #267 리서치 요약 구조화 필드 추가

리뷰어: Claude Code 오케스트레이션 하의 VFF(Sonnet) — 교차 모델 독립 리뷰. 구현에 관여하지 않음.

구현자: Codex(gpt-5.6-sol, effort high, 커밋 `098bdac`).

## Review Summary

FE 리서치 상세 화면에서 AI 브리핑을 "요약 지도"로 활용할 수 있도록, 기존 `ResearchSummaryResponse`와 `ResearchRisk`에 신규 필드를 추가합니다. 엔드포인트 경로·인증·로테이션 방식은 그대로이고 응답 스키마만 확장되는 방식입니다.

변경은 4파일 98줄입니다.

- **스키마** — `ResearchRisk`에 `evidence: list[str] = Field(default_factory=list)`, `ResearchSummaryResponse`에 `stance_comment: str | None = None`, `positive_factors`·`caution_factors`·`next_checks: list[str] = Field(default_factory=list)`, `confidence_basis: str | None = None`가 추가됐습니다. list 필드는 모두 `Field(default_factory=list)`로 선언되어 Pydantic mutable default 함정을 피했습니다.
- **서비스** — `_RiskTemplate`·`_SummaryTemplate` TypedDict에 동일 키가 추가됐고, `_SUMMARY_TEMPLATES` 두 벌에 한국어 점검 유도형 콘텐츠가 채워졌습니다. `get_summary`의 응답 조립 부분에서 신규 필드가 템플릿에서 그대로 매핑되며, 기존 필드와 `asset.id % 2` 로테이션 방식은 변경되지 않았습니다.
- **API 계약 테스트** — `RESEARCH_SUMMARY_CONTRACT`와 `RESEARCH_RISK_CONTRACT`에 신규 키가 추가됐고 nullable 필드는 `(str, type(None))` 튜플로 선언되어 계약 검사를 통과합니다.
- **통합 테스트** — 신규 테스트 `test_get_research_summary_returns_structured_fields_for_all_templates`가 두 asset을 생성해 각 템플릿마다 신규 필드 5종이 비어 있지 않고 `evidence`가 1~2개임을 검증합니다. 기존 `test_get_research_summary_returns_deterministic_mock_data`는 무수정으로 통과합니다(새 필드를 단언하지 않으므로 하위 호환).

보호 파일 `app/api/v1/endpoints/assets.py`와 다른 도메인(reports·signals)은 변경되지 않았으며, 마이그레이션도 없습니다. 설계 문서 `docs/designs/267-research-summary-structure.md`의 범위를 정확히 지켰습니다.

## Suggestions

**S1. 신규 테스트에 결정성 단언이 빠져 있습니다**

`test_get_research_summary_returns_structured_fields_for_all_templates`는 두 asset을 생성하고 각각 한 번씩 호출하는데, 각 asset에 대해 두 번 호출해 응답이 동일한지까지 검증하지는 않습니다. 핸드오프(task-171)의 "결정성: 같은 asset_id 두 번 호출 시 동일 응답" 요건은 기존 `test_get_research_summary_returns_deterministic_mock_data`가 충족하므로 실질 위험은 없습니다. 향후 템플릿이 외부 소스에서 읽도록 바뀔 때를 대비해 신규 테스트에도 동일 asset 재호출 단언을 추가하면 보완됩니다. 심각도: 비차단·저비용 개선.

**S2. 템플릿 콘텐츠의 점검 유도형 톤이 일관되게 유지됩니다**

두 템플릿 모두 `~하세요` 또는 `~살펴야 합니다` 등 점검을 권장하는 문장으로 작성됐으며, 매매 명령형 단정문은 없습니다. 설계(`design-doc` Background 항목)의 "단정 대신 점검 유도형" 원칙과 일치합니다. 문제 없이 채택 가능합니다.
