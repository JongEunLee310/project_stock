# PR #232 로컬 리뷰 — feat: LLM 프롬프트 7종에 한국어 출력 지시 추가

리뷰어: value-for-fable (Sonnet — VFF 위임)

## Review Summary

openai-oauth 프록시 연결 이후 실제 LLM 경로에서 추천 rationale과 관찰메모가 영어로 출력되는
현상을 해결하기 위해, `app/adapters/llm/prompts/` 아래의 시스템 프롬프트 7종에 공통 한국어
출력 지시문을 추가하는 PR입니다.

구조는 단순합니다. `language.py`를 새로 만들어 `KOREAN_NATURAL_LANGUAGE_OUTPUT_INSTRUCTION`
상수 하나를 정의하고, 7종 프롬프트가 이 상수를 각자 참조합니다. 상수형 4종(`STOCK_RECOMMENDATION_SYSTEM_PROMPT`,
`WATCHLIST_OBSERVATION_SYSTEM_PROMPT`, `DASHBOARD_BRIEFING_SYSTEM_PROMPT`,
`PORTFOLIO_BRIEFING_SYSTEM_PROMPT`)은 모듈 레벨에서 `.strip() + "\n\n" + KOREAN_NATURAL_LANGUAGE_OUTPUT_INSTRUCTION`
으로 이어 붙이고, 함수형 3종(`build_analysis_system_prompt`, `build_news_summary_system_prompt`,
`build_thesis_conflict_system_prompt`)은 반환 문자열에 `\n\n`으로 구분해 포함합니다.

지시문은 "자연어 필드(rationale, note, summary, headline, body, risk_checks 등)는 한국어로
작성하고, JSON 키·symbol·enum 값은 원문 그대로 유지하라"는 취지를 영어로 담고 있습니다.
symbol을 영어 그대로 유지하도록 명시한 것은, 추천 서비스(`recommendations_service.py`)가
LLM 응답의 symbol을 후보 목록과 문자열 비교해 필터링하는 구조를 직접 겨냥한 판단입니다.

신규 테스트(`tests/test_prompt_language.py`)는 7개 파라미터로 각 프롬프트에 공통 지시문이
포함되는지 단언합니다. 함수형 프롬프트 3종은 파라미터 평가 시점(pytest 수집 시)에 실제로
호출되므로, import 경로와 JSON Schema 조립이 정상인지도 함께 검증됩니다.

변경 파일: `app/adapters/llm/prompts/language.py`(신설), 프롬프트 7종, `tests/test_prompt_language.py`(신설),
`docs/designs/231-korean-llm-output.md`(신설), `.codex/tasks/task-154-korean-llm-output.md`(신설).

## Suggestions

**S1. 설계 문서의 상수/함수 종수가 구현과 반대로 적혀 있습니다.**

`docs/designs/231-korean-llm-output.md`의 Verified Facts 절은 "상수 3종은 `*_SYSTEM_PROMPT`
문자열, 나머지 4종은 `build_*_system_prompt()` 함수"라고 서술하고, Decisions 절도 "상수 3종은
문자열 말미에 이어 붙이고, 함수 4종은 반환 문자열에 포함한다"고 적고 있습니다. 그러나
실제 구현은 상수형 4종(`stock_recommendation`, `watchlist_observation`, `dashboard_briefing`,
`portfolio_briefing`)과 함수형 3종(`analysis`, `news_summary`, `thesis_conflict`)으로,
설계 문서의 숫자가 뒤바뀐 상태입니다. 핸드오프 문서(`.codex/tasks/task-154-korean-llm-output.md`)는
"상수형 4종/함수형 3종"으로 올바르게 기술되어 있어 구현에는 영향이 없지만, 설계 문서가
미래 독자에게 혼동을 줄 수 있습니다. 두 절의 숫자와 적용 방식 기술을 실제 구현에 맞게
정정하는 것을 권장합니다.

**S2. 함수형 프롬프트 3종의 마지막 줄이 보간 없는 f-string을 사용합니다.**

`analysis.py`, `news_summary.py`, `thesis_conflict.py`에서 반환 튜플의 마지막 요소가
`f"{KOREAN_NATURAL_LANGUAGE_OUTPUT_INSTRUCTION}"` 형태입니다. `{...}` 안에 다른 표현식이
없으므로 `f"..."` 접두사가 없어도 동일하게 동작합니다. 단순히 `KOREAN_NATURAL_LANGUAGE_OUTPUT_INSTRUCTION`
으로 쓰면 의도가 더 명확합니다. 기능 차이는 없으므로 현재 범위에서 머지를 막지 않으며,
후속 정리로 처리해도 무방합니다.

## Questions

**Q1. `risk_checks` 필드가 자유 텍스트인지 구조화된 식별자인지 확인이 필요합니다.**

지시문은 `risk_checks`를 자연어 필드로 분류해 한국어로 출력하도록 요청합니다. `LLMAnalysisResult`의
`risk_checks`가 "매출 성장세 둔화" 같은 서술형 문자열 목록이라면 한국어 출력이 의도에 맞습니다.
반면 `REVENUE_MISS`처럼 코드베이스가 프로그래밍적으로 비교하는 식별자나 enum 값을 담는다면,
"enum values exactly as given" 지시와 충돌해 LLM 응답이 예측하기 어렵게 됩니다. 실제 LLM
경로로 응답을 확인했을 때 `risk_checks` 값이 어떻게 나오는지 확인해 두면 이후 혼란을 예방할
수 있습니다. 현재 스코프의 주요 목표(자연어 필드 한국어화)에는 영향이 없으므로 머지 전
결론을 내릴 필요는 없습니다.

## Final Recommendation

**머지해도 좋다고 판단합니다.** Blocking 항목이 없습니다.

핵심 정확성 관점에서 가장 중요한 지점인 symbol 원문 유지 지시가 지시문에 명시되어 있고,
이것이 추천 서비스의 문자열 비교 필터링을 보호합니다. 공통 상수 1개를 7곳이 참조하는 구조여서
지시문이 바뀌더라도 한 곳만 수정하면 됩니다. 테스트는 7종 프롬프트 각각이 공통 지시문을
포함하는지 직접 단언하며, 함수형 프롬프트 3종은 pytest 수집 시 실제 호출되므로 JSON Schema
조립 경로도 함께 검증됩니다. 기존 테스트를 약화하거나 삭제하지 않았고, 보호 파일 변경도
없습니다.

S1은 설계 문서의 숫자 정정, S2는 불필요한 f-string 접두사 제거, Q1은 실LLM 응답 확인 후
인지해 두면 충분한 사항으로, 현재 범위에서 머지를 막지 않습니다.

최종 머지 권한은 개발자에게 있습니다.
