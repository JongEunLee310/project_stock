## Review Summary

`GET /api/v1/signals`의 `asset_id`를 필수에서 선택(`int | None = None`)으로 완화하고,
미지정 시 전체 시그널을 페이지네이션으로 반환하는 PR입니다.

변경은 엔드포인트·서비스·리포지토리 세 계층에 걸쳐 있습니다. 엔드포인트에서는
`asset_id` 파라미터 타입을 완화하는 한 줄 변경입니다. 서비스 세 메서드
(`list_signals` / `list_signals_expanded` / `count_signals`)는 `asset_id: int | None`을
받아 `None`이면 신규 `list_all` / `count_all` 경로로 분기합니다. 리포지토리에는
`list_all(include_expired, offset, limit)` / `count_all(include_expired)` 두 메서드가
추가됐으며, 정렬은 `list_by_asset`과 동일한 `created_at DESC, id DESC`를 유지합니다.
기존 `list_by_asset` / `count_by_asset`의 시그니처와 동작은 변경 없이 하위호환을
유지합니다.

`expand=asset` 경로는 `list_signals_expanded`를 통해 동일하게 적용되어
`signals-expand-asset.md` §3.2–3.3의 동작을 그대로 이어받습니다. asset 조회 후
시세를 합쳐 `AssetBriefResponse`를 구성하는 로직은 기존 코드를 재사용합니다.

테스트는 핸드오프 요건을 모두 충족합니다. `test_list_signals_requires_asset_id`(422
기대 케이스)는 제거됐고, 전체 조회(`test_list_signals_without_asset_id_returns_all`),
expand 조합(`test_list_signals_without_asset_id_expand_asset_includes_asset_object`),
`include_expired` 조합(`test_list_signals_without_asset_id_respects_include_expired`)
세 케이스가 추가됐습니다. `signal_type` 값은 `SignalType.WATCH.value` 패턴을 사용해
문자열 리터럴 직접 입력을 회피하고 있어 픽스처 규율을 준수합니다.

## Suggestions

**S1. `list_signals_expanded`에서 중복 asset_id 제거 없이 N+1 쿼리 발생 가능**

`service.py`의 `list_signals_expanded`가 `asset_ids = [signal.asset_id for signal in
signals]`를 그대로 순회하며 `asset_repo.get_by_id`를 호출합니다. 같은 asset에 시그널이
여러 개 있으면 동일한 id로 중복 쿼리가 발생합니다. 예를 들어 AAPL 시그널 5개, MSFT
시그널 3개가 한 페이지에 들어오면 8번 쿼리 중 실질적으로 필요한 것은 2번입니다.
`list(dict.fromkeys(asset_ids))`로 선 중복 제거 후 조회하면 해소됩니다.

전체 조회 경로가 새로 열리면서 한 페이지에 여러 asset의 중복 시그널이 노출될 빈도가
높아지므로, 기존 asset-specific 경로보다 실제 영향이 큽니다. 기능 결함은 아니고
페이지 크기로 bounded 되어 있으므로 Blocking은 아닙니다. 심각도: 비차단·후속 개선.

**S2. 전체 조회 경로의 페이지네이션 오프셋 경계 테스트 없음**

신규 테스트 3개는 기본 페이지 크기(20) 안의 항목만 다루어 `offset` 동작을 직접
검증하지 않습니다. `PaginationParams`는 기존 코드라 위험이 낮고, `list_all`이 동일한
`offset`·`limit`을 받아 같은 방식으로 처리하므로 구조적 문제는 없습니다. 다만
`size=1&page=2` 같은 경계 케이스 커버리지가 있으면 리그레션 안전망이 더 견고해집니다.
심각도: 비차단·선택적 후속.
