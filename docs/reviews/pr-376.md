# PR #376 로컬 리뷰 — 뉴스 인텔리전스 토픽 맵 계약 (#303)

## Review Summary

뉴스·공시 인텔리전스(에픽 #307) 1차 계약의 세 번째 단위로, `GET /api/v1/news-insights/topics/map`을 추가합니다. #301 브랜치 위에 스택된 PR이며 커밋은 1건입니다. 단일 관심사(토픽 맵)이므로 Part 분할 없이 이어서 설명합니다.

백엔드가 관계 계산을 완료한 nodes·edges를 반환하고 FE는 렌더만 하도록 설계했습니다. `service.py`는 momentum 기준으로 활성 토픽을 `limit`만큼 제한하고, 관련 `topic_keywords`·`keyword_relations`(#305 모델)를 조회해 node(`TOPIC`/`KEYWORD`)와 edge를 조립합니다. `schema.py`에는 `TopicMapQuery`·`TopicMapNode`·`TopicMapEdge`·`TopicMapResponse`를 추가했고, node는 `mention_count`·`momentum_score`·`sentiment_score`·`category`를, edge는 `strength`·`cooccurrence_count`를 담습니다. 라우트는 기존 `get_current_user`·`success` 엔벨로프를 재사용하고 `window`(`^[1-9]\d*[hd]$`)·`limit`(1~100) 입력을 검증합니다. core 파일 변경은 없습니다.

이번 리뷰는 설계 §4.4 계약 일치, 연관 강도와 감성의 분리, 범위 이탈 여부를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. node `sentiment_score`가 0.0~1.0 범위 — 방향은 중앙값 기준 해석 규약이 필요, #305 모델 계약과는 일치.** 토픽 맵 node는 방향 필드 없이 `sentiment_score`(0~1)만 가지므로, 부정/긍정은 0.5 중앙값 기준으로 해석하는 규약(0=강한 부정, 1=강한 긍정)이 전제됩니다. 이는 #305에서 `topic_clusters.sentiment_score`에 이미 부여된 CHECK 0.0~1.0 제약과 일치하므로 이 PR의 문제가 아니라 프론트 표시 규약으로 확정하면 됩니다. 부호 있는 감성(-1~1)이 필요하면 #305 모델 변경이 선행돼야 하며 현재 범위 밖입니다. FE 연동(project_stock_frontend#202) 시 해석 규약을 명시하기를 권합니다.

**S2. `market` 파라미터 수용 후 미적용 — 1차 seed 계약의 알려진 한계.** #301·#303 공통으로, `market`은 검증·수용되나 #305 모델에 시장 식별 컬럼이 없어 DB 필터로 작동하지 않습니다. 1차는 계약 고정이 목적이므로 허용 가능하며 PR 본문에 명시돼 추적 가능합니다. 실데이터 연동 시 저장 모델 연결이 필요합니다.
